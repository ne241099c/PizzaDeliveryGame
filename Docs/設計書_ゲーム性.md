# 設計書: ゲーム性(ルール確定版・たたき台)

M3までで「道を組んで時間を比べる」パズルの部品はできた。この設計書は、それを**ゲームとして成立させる**ための
ルールを確定する。以降のM4(時間経過・注文発生・期限・スコア)は、この内容を元に作る。
日をまたぐ経営(お金・雇用・成長)は `設計書_経営.md` を参照。

## 1. 確定事項

| 項目 | 決定 |
|---|---|
| ゲーム全体の形 | 日をまたいで終わりなしで続く経営。得点はそのままお金(売上) |
| 時間の進み方 | 完全なリアルタイム(ルートを組んでいる間も時間は進む) |
| 注文の頻度と期限 | プレイヤーが「お届け目安時間」を設定する。**短いほど注文が来て、長いほど来にくい**(4章) |
| 遅延のペナルティ | 遅れた秒数に応じて得点が減る。さらに**評判**が下がり、以後の注文が減る |
| 配達員 | **人数は固定しない**(名簿に何人でもいる)。複数人が並行して配達する |
| 配達員の能力 | **6つの能力**。人ごとに得意が違う(6章) |

## 2. 1日の流れ

```
[開店] 営業時間タイマー開始(初期値: 現実時間で5分)
   ↓
 注文が自動で発生(頻度は、お届け目安時間と評判で決まる)。各注文に期限がつく
   ↓
 プレイヤーが 注文を選ぶ → 待機中の配達員を選ぶ → ルートを決める → 出発
   ↓                                                       ↑
 配達員が道順どおりに移動(別の注文は別の配達員に任せられる)
   ↓
 配達先に到着した時点で、得点と評判が確定
   ↓
 店に戻ると配達員は待機中に戻り、体力が回復していく
   ↓
[閉店] 営業時間が尽きたら新規注文を止める。配達中の分は完了まで続行
   ↓
 全員が帰還したら精算画面(その日の収入・損益。コストは設計書_経営.md)
```

- お届け目安時間は**営業中もいつでも変えられる**。変更は、その後に発生する注文から反映する
- 閉店時に未出発の注文は0点(キャンセル扱い)。減点は初期値0で、調整項目にしておく
- 得点は配達先への**到着時点**で確定する(店への帰還は待たない)
- M4の時点では、精算は「得点・配達数・遅延数・キャンセル数・評判」を見せる簡易な結果画面でよい

## 3. 時間の単位(重要)

所要時間のサンプルは**ルート1本が3〜7秒程度**しかなく、リアルタイムで管理するには短すぎる。
そのため、**計算した移動時間にTimeScaleを掛けて、現実の時間に変換する**。

```
現実の移動時間(秒) = 計算した所要時間 × TimeScale
```

- 初期値: **TimeScale = 5**(最短のまとめ配達 約7秒 → 約35秒)
- 営業時間5分(300秒)で、配達員1人あたり4〜8回の出発が目安
- 画面に表示する時間・期限は、すべて現実の秒数(TimeScale適用後)で統一する

## 4. 注文・お届け目安時間・需要・評判

### お届け目安時間(プレイヤーが設定)
- 「注文から配達先に着くまでの約束の時間」。**現実の秒数**で、スライダーで設定する(初期値 60秒、上限 240秒)
- **下限**は、一番遠い配達先に「最強の配達員が最短で着く時間」× TimeScale × 1.1。物理的に届かない約束はできない
- 各注文の**期限 = 発生時刻 + お届け目安時間**
- 画面には、設定した目安時間、需要の目安(例: 約25秒に1件)、各配達先の最短到着時間(参考)を並べて出す。
  判断材料を見せ、**「短く約束して稼ぐか、長くして楽をするか」**を決められるようにする

### 需要(注文の発生頻度)
```
需要係数 = clamp((基準目安時間 ÷ お届け目安時間) ^ 0.7, 0.4, 2.0)      基準目安時間 = 60秒
評判係数 = 0.6 + 0.8 × 評判 ÷ 100                                          評判 0〜100
注文の発生間隔 = 基準間隔 ÷ (需要係数 × 評判係数)     基準間隔 = 25秒、±30%ゆらぐ
```

| お届け目安時間 | 需要係数 | 発生間隔(評判50) |
|---|---|---|
| 30秒 | 約1.62 | 約15秒に1件 |
| 60秒 | 1.00 | 約25秒に1件 |
| 120秒 | 約0.62 | 約40秒に1件 |
| 180秒 | 約0.46 | 約54秒に1件 |

短く約束すれば注文は増えるが、期限が厳しくなって遅れやすい。長くすれば楽だが、注文が来ない。

### 評判(0〜100、初期値 50)
| できごと | 評判の変化 |
|---|---|
| 期限内に到着 | +1 |
| 遅れて到着 | −min(5, 1 + 0.1 × 遅れた秒数) × (1 − 0.5 × 接客) |
| 注文がキャンセル(未出発のまま0点) | −5 |

評判が下がると注文が減り、稼ぎが落ちる。**遅れが続くと取り返しにくくなる**ので、目安時間を攻めすぎるリスクになる。
(評判を日をまたいで持ち越すのはM5。M4では1日ごとに50から始める)

### 注文の中身
- 配達先: マップ上の配達先からランダム
- `Order` に `SpawnedAt` と `Deadline`(現実の秒)を持たせる
- 待機中の注文には、期限までの残り時間を表示する

## 5. 得点

```
1件の得点 = max(0, 基本点 − 遅れた秒数 × 減点/秒) + チップ

基本点 = 100、減点/秒 = 5(20秒遅れて0点)
チップ = 期限内のときだけ 基本点 × 0.2 × 接客
```

- 期限内に着けば満点(+チップ)。早着ボーナスは入れない
- **0点になるまで遅れた未出発の注文は自動キャンセル**して注文リストから消す(要確認)
- まとめて回る場合、**後に回した注文ほど遅れやすい**。ここが「効率を取るか、急ぎを先に出すか」の判断になる

## 6. 配達員

### 人数
- 名簿(リスト)に**何人でも**入れられる作りにする。M4では、Inspectorで開始メンバーを決める
- 配達員が増えても一覧が破綻しないよう、一覧はスクロール式にする
- 雇用・解雇はM5(お金の仕組みと一緒に作る)

### 6つの能力(0〜1。積載量だけ整数)
| 能力 | 効果 |
|---|---|
| 運転 | 移動速度。`速度係数 = 0.7 + 0.6 × 運転`(大通りにも裏道にも効く) |
| 土地勘 | 裏道での遅れにくさ。裏道の所要時間 × `(1 + (1 − 土地勘) × ペナルティ係数)`(M3の「スキル」はこれに当たる) |
| 積載量 | 一度に運べる注文数(1〜2。3以上は経路探索を広げた後) |
| 接客 | 期限内到着のチップ。遅れたときの評判の下がりを軽くする(4・5章) |
| 体力 | 疲れにくさ。体力の現在値は配達で減り、待機で回復する。下の「体力」を参照 |
| 安全性 | 事故の起こりにくさ。下の「事故」を参照 |

### 体力
- 配達員は「現在体力」(0〜1、満タンで開始)を持つ。**能力の「体力」は、減りにくさと回復の早さ**を決める
- 配達中は毎秒 `0.004 × (1.5 − 体力)` 減り、待機中(店にいる間)は毎秒 `0.003 × (0.5 + 体力)` 回復する(初期値の目安)
- 出発時の現在体力が速度に効く: `速度補正 = 0.7 + 0.3 × 現在体力`。疲れた人は遅い
- 簡略化のため、**出発時の値で速度を固定し、消耗は帰還時にまとめて反映**する(配達中に速度は変わらない)
- 「よく働く人を酷使するか、休ませて回すか」が判断になる

### 事故
- 配達中、**道1本を通るたび**に事故の抽選をする:
  `事故確率 = 0.05 × (1 − 安全性) × 道の係数(大通り1.0、裏道1.5) × (1 + (1 − 現在体力))`
- 事故が起きたら、その配達員は**15秒(現実)止まる**(到着が遅れる)。修理費はM5(経営)で加える
- 安全性の低い人が疲れた状態で裏道を走ると危ない。**「速いが危うい人」**に重要な注文を任せるか、が判断になる

### 状態
| 状態 | 内容 |
|---|---|
| 待機中(Idle) | 店にいる。注文と組み合わせて出発できる。体力が回復する |
| 配達中(Delivering) | 決めたルートの道を順に移動している。ルートの変更はできない |
| 帰還中(Returning) | 配達先をすべて回り終え、店へ戻っている。着いたら待機中に戻る |

### 配達員の例(M4の動作確認用)
| 名前 | 運転 | 土地勘 | 積載量 | 接客 | 体力 | 安全性 | 持ち味 |
|---|---|---|---|---|---|---|---|
| Minato | 0.8 | 0.9 | 1 | 0.4 | 0.6 | 0.7 | 速くて道に強い。1件ずつ |
| Aoi | 0.6 | 0.6 | 2 | 0.8 | 0.7 | 0.8 | 接客が良く、まとめられる |
| Ren | 0.5 | 0.3 | 2 | 0.5 | 0.9 | 0.4 | タフだが裏道が苦手で荒い |
| Sora | 0.9 | 0.4 | 1 | 0.3 | 0.4 | 0.3 | 最速だが疲れやすく危うい |

人数は固定ではないので、これは動作確認用の名簿。Inspectorで増減できる。

## 7. 操作の負担への対処(完全リアルタイムを選んだ影響)

道を1本ずつクリックしてルートを組む方式は、時間が進み続ける中では**操作が重くなる**。次の手当てを入れる:

1. **推奨ルートで即出発できるボタンを用意する**(`Dispatch with suggestion`)。忙しいときは1クリックで出せる
2. **ルート編集中も時間は進む。** ただし調整項目として「編集中の時間の進み(初期値1.0倍)」を持たせる。厳しければ0.3倍などに下げる
3. **お届け目安時間を長くして、注文を減らす**ことも、負担への対処になる(これがこのゲームの持ち味)
4. 一度に選べる注文は2件まで(経路探索の対象と揃える)

## 8. 調整項目(Inspectorで変えられるようにする)

| 項目 | 初期値 |
|---|---|
| 営業時間 | 300秒(現実時間) |
| TimeScale | 5 |
| お届け目安時間(初期値、範囲) | 60秒(下限は計算、上限240秒) |
| 基準目安時間、需要の指数 | 60秒、0.7 |
| 注文の基準間隔 | 25秒(±30%) |
| 評判(初期値、各変化量) | 50、4章の表 |
| 基本点、減点/秒 | 100、5 |
| チップの割合 | 20% |
| 閉店時の未出発注文の減点 | 0 |
| ルート編集中の時間の進み | 1.0倍 |
| 体力の消耗・回復の係数 | 0.004、0.003 |
| 事故の基準確率、停止時間 | 0.05、15秒 |
| 開始メンバー | 6章の例 |

## 9. 今のコードとの差(やること)

| 追加・変更 | 内容 |
|---|---|
| GameClock | 現実時間の進行、営業時間の管理、TimeScale |
| 配達員データ | 「スキル1つ」を6能力に拡張。名簿を何人でも扱える作りにする。移動時間の計算に運転・土地勘を反映 |
| OrderSpawner | 注文の自動発生。お届け目安時間と評判から頻度と期限を決める |
| お届け目安時間の画面 | スライダー、需要の目安、各配達先の最短到着時間 |
| 配達員の状態管理 | Idle / Delivering / Returning、道に沿った移動、積載量での注文数の制限 |
| 出発と到着の処理 | 今の「Complete route(即時完了)」を「出発」に変える。到着時に得点・評判・チップを確定 |
| 体力と事故 | 現在体力の増減、事故の抽選と停止 |
| 結果画面 | 得点、配達数、遅延数、キャンセル数、評判 |

M3で作った`ManualDeliveryRoute`、`RoadPathfinder`、`MapManager`は、基本そのまま使える見込み。
ただし移動時間の計算が「スキル」から「運転・土地勘」に変わるため、`MapManager`の時間計算は変更が必要。
`DeliveryFlowController`と`DeliveryPlannerUI`は大きく変わる。

## 11. 未確定・遊んで決めること
- 営業時間5分、TimeScale 5が適切か(長い/短いは触って判断する)
- お届け目安時間の初期値・範囲、需要の指数(0.7)が「短く約束するほど儲かる」に偏りすぎないか
- 評判の変化量が、遅延の怖さとして適切か(下がりすぎて取り返せなくならないか)
- 体力・事故の係数が、面白さにつながっているか(うっとうしくないか)
- 完全リアルタイムで、道を1本ずつクリックする操作が回るか(7章の手当てで足りるか)
- 未出発で0点になった注文を、自動キャンセルにするか、残すか
- 早着ボーナス、調理時間(焼き時間)は後から足す
