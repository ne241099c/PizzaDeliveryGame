# 設計書・計画書: 店内シーン(ピザ作りと配達を、1つの空間でつなぐ)

**狙い**: 営業中は画面を切り替えず、**1つの「店の中」**で、ピザを作る → 箱に入れる → 配達員に渡す → ルートを決めて送り出す、までを一続きの行為にする。
調理シミュレーターのように**物を直接つかんで動かす**。ただし、調理は**自分でやってもよいし、内勤(厨房スタッフ)を雇って任せてもよい**。任せれば、自分は配達の判断に集中できる。

決定事項(ユーザー確認済み): **2Dのトップダウン**。調理は**自分 or 内勤**。

実施の順番: **この設計書(S2-0〜S2-8) → 画面デザイン(`設計書_画面デザイン.md`)** の順に、一部を並行して進める(10章)。
ビルド・README(`計画書_ビルドとREADME.md`)は、これらが終わるまで**保留**する。

## 1. 今の問題と、作り直す理由

| 今 | 問題 |
|---|---|
| 営業画面が、地図・注文・配達員・計画パネルのパネルの集まり | 「ピザ屋を営む」感じがなく、操作がバラバラ |
| 調理は、待ち行列とゲージだけ(M7のC-1・C-2) | ピザを作っている感がない。何も触れない |
| 調理と配達が別々の処理 | 「作って、渡して、送り出す」の流れがない |

**再利用するもの(作り直さない)**: 注文の発生・期限・得点・評判・精算・セーブ・設備の費用、配達員の移動・事故・ルート作成のロジック(`ManualDeliveryRoute`、`RoadPathfinder`、`DeliveryPlannerUI`の中身)、調理の窯の台数と調理時間の設定。
**作り直すもの**: 営業画面の見た目と操作(S-3で作った配置)、調理の中身(待ち行列 → 工程と物)。

**指示盤(地図)の画面の決まり(改訂)**
- 地図が主役。**画面全体を地図にし**、操作の部品は縁に小さく重ねる(壁に貼った絵ではなく、「地図を開いた」状態)
- 厨房側から指示盤へ移るカメラのパンは残してよいが、着いた先は**地図が全面**(ワールドの壁の絵に縛られない)
- 操作の順番を**手順バー**で常に見せる。いまの手順は黄色で強調、終えた手順は緑のチェック。地図上に「いまここ」の吹き出しを出す(手順が進むと次の案内に変わる)
- 手順は4つ: ①配達員を選ぶ(カウンターの配達員をクリック) ②箱をバッグに入れる(ドロップ) ③地図で届け先のピンを、行く順番にタップ(ルートが引かれる) ④出発(`出発` / `おすすめ経路`)。1件でも入れば③④に進める
- 出す情報は最小限: 配達員の名前と状態、バッグ(n/最大)、行く順番、所要秒数と「速い/遅い」、お届け目安に間に合うか。**能力値・内訳・長い説明は出さない**(詳細は選択時のツールチップ)
```

## 3. 物を動かす仕組み(「手」)

- **つかむ**: 物をクリック(またはドラッグ開始)すると、**手に持つ**。持った物はカーソルに追従する(少し遅れて、影を付けて浮かせる)
- **置く**: 置ける場所の上でクリック(またはドラッグ終了)。置ける場所は**光る**。置けない場所では、元の位置に戻る
- **持ったまま、カメラを動かせる**(パンしても手の中身は残る)。持ったままQ・Eで厨房から指示盤へ移れる
- **取り消し**: 右クリックかEscで、元の場所へ戻す
- 持てるものは**1つだけ**(箱は、袋にまとめて渡すときだけ複数)
- 物の見た目は、重なり・影・置いたときの小さな弾み(0.1秒)で「触れている感」を出す(物理演算は使わない)
- キーボードだけでも操作できる補助(Tabで選択、Enterで置く)は、後で付ける(任意)

## 4. ピザを作る工程

### 工程(1枚のピザ)
| 順 | 工程 | 手動の操作 | 内勤に任せたとき | 品質への影響 |
|---|---|---|---|---|
| 1 | 生地 | 材料棚の生地をクリック → 作業台に置く(自動で丸く伸びる) | 自動 | なし |
| 2 | ソース | おたまをつかみ、生地の上を**なぞる**。塗れた割合が使われる | 自動 | 塗れた割合(70%未満は★減点) |
| 3 | チーズ | チーズの容器を生地の上に**ドロップ**(ふりかけの動き) | 自動 | なし(量は固定) |
| 4 | 具 | 注文の指定の具のトレイを生地の上に**ドロップ**(ペパロニなど、1〜2種) | 自動 | **指定どおりの具か**(間違えると★減点) |
| 5 | 焼く | ピザをピールに乗せ、**窯に入れる**。窯のゲージが帯に入ったら**取り出す** | 自動(帯の真ん中で取り出す) | 取り出しのタイミング(帯の中なら★up) |
| 6 | 梱包 | 保温棚のピザを**箱にドロップ** → 箱を**閉じる**(クリック)。伝票が自動で貼られる | 自動 | なし |

- 1枚あたりの手動の操作は **8回前後**(クリック・ドラッグ・ドロップ)。所要は **10〜14秒**が目安
- 具が1種なら具の工程は1回、2種なら2回
- **窯と作業台が資源**。台数が足りないと、順番待ちになる(設備で増やす)

### 時間(秒は現実の秒。すべて調整項目)
| 工程 | 手動(目安) | 内勤の自動(手際0.5のとき) |
|---|---|---|
| 生地 | 操作時間のみ | 1.0 |
| ソース | 操作時間のみ | 2.0 |
| チーズ・具 | 操作時間のみ | 3.0 |
| 焼く | 4.0(窯の時間) | 4.0 |
| 梱包 | 操作時間のみ | 2.0 |
| **合計** | **自分の腕しだい(約10〜14)** | **約12**(M7の `cookSeconds` と同じ) |

- 窯の時間は、手動でも内勤でも**同じ**(窯は窯)。他の工程は、**手際**で内勤の速さが変わる(手際が高いほど速い。`時間 ×(1.3 − 0.6×手際)`)
- **自動プレイと、お届け目安の下限**は、内勤の自動(約12秒)を基準にする(M7の調整がそのまま使える)

### 品質(★1〜3)
- 工程ごとの出来から点を集める: **ソース**(70%以上=1点)、**具**(指定どおり=1点)、**焼き**(帯の中=1点)。合計 0点 → ★1、1〜2点 → ★2、3点 → ★3
- 内勤の場合は、各工程の点を**丁寧さ**で確率的に決める(丁寧さ0.5なら各工程の成功が約50%+)
- 品質の効果:

| 品質 | 得点ボーナス(期限内のみ) | 評判 |
|---|---|---|
| ★1 | 0 | 変化なし |
| ★2 | +8 | 変化なし |
| ★3 | +20 | +0.5 |

> M7の「完璧ボーナス +15」は、この品質ボーナスに置き換える(焼きの帯=1点として吸収)。

### 失敗(焦げ)
- 窯に入れた後、取り出さないと焦げる: 帯を過ぎて **+5秒**で「焦げ」(品質は★1固定、見た目も焦げ)。**内勤が窯の担当なら、自動で取り出す**ので焦げない
- 自分で焼くときだけ起こる。**任せる理由**になる(忙しいと焦がす)

### ピザの種類(任意。S2-6)
| 種類 | 具 | 基本の得点 | 工程の違い |
|---|---|---|---|
| マルゲリータ | バジル | 100 | 標準 |
| ペパロニ | ペパロニ | 120 | 具の工程が1回 |
| シーフード | えび+いか | 150 | 具の工程が2回、焼きが+1秒 |

- 最初はマルゲリータのみ。メニュー拡張(設備)で解禁。注文は、解禁済みの種類から発生
- 伝票に、種類と**必要な具のアイコン**を出す(どのトレイを使うかが一目で分かる)

## 5. 内勤(厨房スタッフ)

- 配達員とは**別の職種**。求人に「内勤」の候補が出る。雇用・解雇・日給・採用費は、配達員と同じ仕組み(`RecruitmentManager`)
- 能力は2つ(0〜1): **手際**(工程の速さ)、**丁寧さ**(品質)
- 日給: `40 + 50 × (手際 + 丁寧さ)`(調整項目)。例: 手際0.5・丁寧さ0.5 → 90
- **名簿の上限(初期4)は、配達員と内勤の合計**。人数の取り合いが判断になる(店舗拡張で増える)
- 開始時の名簿: 配達員2人(Aoi、Ren)+ **内勤1人(見習い)**。内勤を外せば、自分で全部作る(自由)
- **担当の割り当て**:
  - 伝票は、**既定では内勤に自動で回る**(空いている内勤がいて、作業台・窯が空いていれば)
  - **自分でやる**: 伝票を**つかんで、作業台に置く**と、その注文は自分が作る(内勤は取らない)
  - 内勤が手一杯、または内勤がいなければ、伝票は待つ(自分が取ってもよい)
- 内勤の見た目: 作業台・窯のそばに、キャラ(丸いアイコン+頭文字)が立ち、作業中は動く(手元のゲージ)
- 成長(経験・訓練)は、**後回し**(M8以降)。まずは能力を固定にする
- 内勤は、作業台・窯を**配達員の人数とは関係なく**使う(作業台1台につき内勤1人)。設備で作業台を増やせる(S2-4)

## 6. 配達との接続(シームレスな部分)

### 流れ
1. 焼き上がり → 梱包 → **箱(伝票つき)**ができる。**受け渡し**の台に置かれる
2. **箱をつかんで、カウンターの配達員の上にドロップ** → 配達員の**袋**に入る(積載量の上限まで。2件)
   - すでに積載量いっぱいなら、置けない(理由を表示)
3. 袋に1件以上入った配達員を**クリック**すると、カメラが**指示盤へパン**し、地図に**その配達員の届け先**が表示される。ここで**道を1本ずつ選んでルートを作る**(既存の仕組み)。個別配達との比較も出る
4. `出発` か `推奨経路で出発`。配達員がカウンターから消え、地図上を動き始める(材料費20/件は出発時に払う。従来どおり)
5. 配達中は、指示盤で動きを見る。**別の区画にいても**、到着・事故・帰還は通知される
6. 帰還した配達員は、カウンターに戻る(体力の回復が始まる)

### バッグの大きさ(一度に運べる数)の成長
- 既存の**積載量**(能力。訓練・成長で上がる)が、バッグの大きさ。バッグには**空きスロット(点線の「+」)**を並べ、まだ使えない段階は点線のまま見せる
- 成長の道筋を、配達員カードに1行で示す(例: 「積載量 3 → 4(トレーニング ¥380)」)
- 上限と費用の曲線は、**S2-0で現状(上限・訓練費・設備)を調べて報告**させ、私が決める。目安: 一度に運べる数が増えるほど、ルートの組み合わせ(まとめ配達)の面白さが増える。ただし、地図と目安時間の調整が必要
- 設備の候補(任意): 「大きなバッグ」(全員の積載量+1。費用・維持費は調整項目)

### 配達員の選び方
- 既存どおり、**待機中**の配達員だけ受け取れる(配達中・帰還中は、カウンターに「不在」の札)

### 箱が溜まったとき
- 受け渡しの台に置ける箱は **6個まで**。それ以上は、梱包できない(焼き上がりが保温棚に溜まる)
- 期限が切れた注文は、箱もピザも**キャンセル**になり、片付けられる(従来のキャンセル規則)

## 7. 既存への影響

| 対象 | 変更 |
|---|---|
| 注文の状態 | `調理待ち / 調理中 / 焼き上がり` に加え、**`梱包済み` / `袋に入った`** を追加。出発できる条件は「**袋に入っている**」 |
| 調理(M7 C-1・C-2) | 待ち行列とゲージ → **工程の状態機械+物**。`cookSeconds` は、内勤の標準の合計時間として再利用。窯の台数の設備は、そのまま使う |
| お届け目安の下限 | `+ cookSeconds`(内勤の標準)は変えない |
| 配達員のロジック・ルート作成 | **変更しない**。指示盤に移して使う |
| 営業画面(S-3) | **置き換える**(店内シーン)。上の帯・伝票は、HUDに引き継ぐ |
| 設備(M7) | 窯の台数はそのまま。**作業台の増設**を追加(1→2→3台: 400 / 700、維持費 +15/日) |
| 名簿・求人・日給 | **内勤を追加**。上限は配達員と合計 |
| セーブ | 内勤、作業台の段階を追加(営業中はセーブしない既存方針は同じ) |
| 自動プレイ | 調理は**内勤の自動(約12秒、品質は確率)**で動く。手動の操作はしない。出発・雇用・設備の方針は既存どおり。**調理スタッフの雇用方針**を追加 |
| 検証(3,772項目) | 既存は、通り続ける。新しい検証を追加 |

> **守ること**: `ManualDeliveryRoute` と `RoadPathfinder` は変更しない。ゲーム全体のロジック(得点・評判・精算の式)の変更は、品質ボーナスの追加のみ。

## 8. 実装の方針(技術)

| 方針 | 理由 |
|---|---|
| 店内は**ワールド空間の2D**(SpriteRenderer+Collider2D)。HUDはCanvas(オーバーレイ) | 物を動かす・当たり判定にはワールド空間が向く。HUDは既存のUIの資産を使う |
| `HandController`(手)を作る。つかむ・置く・戻す、ドロップ先の判定(`Collider2D` の `IDropTarget`)を担う | 物の動かし方を一か所にまとめる |
| 区画ごとに `Zone` を作り、カメラは `ShopCameraRig` が管理(パン・全体表示・通知) | 「画面の切り替え」ではなく「カメラの移動」にする |
| ピザは `PizzaItem`(状態、品質、注文ID、見た目の層)。工程は `PizzaStage` の状態機械。手動と内勤は、**同じ状態機械を別の「作り手」が動かす**(`IPizzaWorker`: Player / Staff) | 手動と自動で、ルールが食い違わないようにする。検証もしやすい |
| 指示盤は、**地図を画面全体に表示する地図ビュー**にする(既存の `MapViewportUI` などを拡張。方式はS2-0で選ぶ)。既存の操作を壊さない | 地図・ルート作成のロジックを再利用する |
| 画面の非表示は CanvasGroup(既存方針)。Canvasの子の並びに依存する処理に注意 | M5-2・S-1の教訓 |
| 数値はすべて `[SerializeField]`(Inspector) | 既存方針 |

### 地図ビューの要件(大きな地図でも動く)
- **見た目と操作はGoogleマップ風**: ドラッグで移動、ホイール(ピンチ)でズーム(カーソル位置が中心)、+/−ボタン、現在地(店)へ戻る、ミニマップ(見えている範囲の枠つき)、混雑レイヤーの切り替え
- **大きな地図でも軽く**: 地図を**固定サイズの区画(チャンク)**に分けて描き、**画面に映る区画だけ**を描画する(視錐台カリング)。区画の絵は、必要になったときに生成してキャッシュ。ズーム段階(LOD)ごとに、道の太さ・名前札・小さな建物の表示を切り替える(遠いときは大通りと主な地名だけ)
- ピン・ルート・配達員の印は、ズームしても**画面上の大きさを保つ**(最小16px)。ピンが密集したときは、ズームアウト時にまとめて数字で表示
- 目標: 現在の地図の10倍の道の数でも、60fpsを保てる設計にする(実測はS2-0・S2-Mで)。`MapDefinition` のデータ形式は変えない
- 地図の描画は**データから自動**(街区・建物・道・名前札)。手で置く飾りは別の層

## S2-4: 内勤

**仕様**: 5章。

## S2-7: 自動プレイ・検証・測定

**仕様**
- 自動プレイが、店内シーンの変更後も動く(調理は内勤の自動、手動の操作はしない)。計算式を複製しない
- 方針に **内勤の雇用**(する / しない)を追加。「しない」は、調理を**自動調理の代役(かんたん調理)**が行う(自動プレイだけの仕組み。手際0.5・丁寧さ0.5相当)
- 次の比較を、同じシードで30日:

| 比較 | 内勤 | 設備 | 見たいこと |
|---|---|---|---|
| J | 1人(開始時のまま) | しない | 標準の遊び方の、収支の安定 |
| K | 1人 | する | 作業台・窯の増設の効果 |
| L | 2人 | する | 内勤を増やす効果と、名簿上限の取り合い |

**調整の目標**: 内勤1人で、標準(60秒)が安定して黒字になる(M6・M7の調整から大きくずれない)。内勤を増やすと稼ぎが伸びるが、名簿の上限と日給で頭打ちになる。**数値は変えず、結果を報告して判断を待つ**。

**指示文**
> 自動プレイと検証を、店内シーンに対応させてください(`Docs/設計書_店内シーン.md` のS2-7)。自動プレイでは、調理は内勤の自動調理(手動の操作はしない)で動くようにし、内勤の雇用の方針(する / しない)を追加してください。「しない」の場合は、自動プレイだけの代役(手際0.5・丁寧さ0.5相当)が調理するようにしてください。計算式は複製せず、実際の処理を呼んでください。次の3通りを同じシードで30日ずつ実行し、CSVと要約を報告してください。J: 内勤1人・設備なし。K: 内勤1人・設備あり。L: 内勤2人・設備あり。数値は変更せず、報告後に私の判断を待ってください。既存の全検証が通ることを確認し、検証の件数を `Docs/Handoff/` に更新してください。
