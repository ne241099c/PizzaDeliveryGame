# M3 実装サマリー：道を選んでルートを作る

更新: 2026-10-21

M3の締め判断・Play結果・M4の優先順位は [M3_Closeout.md](M3_Closeout.md) を参照。

## 現在の遊び方

正式Scene: `Assets/Scenes/SampleScene.unity`。Playで新しい画面を生成する。

1. 左の注文を1〜2件選ぶ。黄色が選択中。再クリックで解除。
2. 配達員を1人選ぶ。水色が選択中。
3. 店舗から始め、地図上の道の中央あたりを順番にクリックする。
4. 現在地につながる道が1本ずつ追加される。右側の `NEXT ROADS` のボタンでも同じ操作ができる。
5. 選んだ注文の配達先をすべて通り、好きな帰り道で店舗へ戻る。
6. `Complete route`で完了する。初期設定では1件100点。対象注文と選択状態を解除する。
7. `Reset`で注文2件・スコア0からやり直す。

現在地は地点名の `*` で示す。青は次に進める道、緑は通った道、黄色は最後に追加した道。
同じ道をもう一度選ぶと引き返せる。配達済み地点の再通過・途中の店舗への帰還も可能。
`Undo last road`で1本戻し、`Clear route`で最初から描き直す。
地図上のホイールでズーム、中ボタンのドラッグで移動、`Fit`で全体表示する。
右の道路候補とルート履歴はスクロール可能。

## 個別配達との比較

右側に `Individual reference` と、選択した注文を個別に最短で往復した参考時間を表示する。
同じ配達員・交通量・スキル補正を使い、各往路・復路を別々に探索して合計する。
自作ルートが全配達先を訪問し、店舗へ戻ったら、参考時間との差を表示する。
短ければ `Saves ...s`、長ければ `Slower by ...s`、同じなら `Same time`。
途中のルートは未走行部分があるため、参考時間だけ表示し、差の判定は保留する。
完了ボタンを押した後も比較結果を残す。

初期設定・注文2件では、Minatoの個別参考は13.12秒、推奨まとめルートは6.86秒で6.26秒短縮。
Renの個別参考は約14.07秒、推奨まとめルートは約7.33秒で約6.73秒短縮。
自作ルートで配達先の間に店舗へ戻れば `Individual route`、戻らず回れば `Combined route` と表示する。

ルート管理と経路探索の解説は [M3_RouteCodeGuide.md](M3_RouteCodeGuide.md) を参照。

## 推奨ルートは任意の1件だけ

注文・配達員を選ぶと、右下に `Optional suggestion: ... / Use this route` を表示する。
押した場合だけ、現在のルートを推奨ルートで置き換える。自動適用はしない。
適用後もUndo・道路追加・全消去できる。

推奨は選んだ注文の配達先を回り、店舗に戻る最短時間の道順。
道路グラフ上のDijkstra法と、現在の注文上限2件の訪問順比較で1件を求める。
大通り・裏道を区間ごとに選び、配達員スキルも考慮する。

従来の「個別4候補・まとめ4候補から選ぶ」画面は廃止した。
個別配達のように途中で店へ戻る道順も、まとめて回る道順も、プレイヤーが同じ編集操作で自由に作る。
帰り道を行きと同じ道に固定する処理は使わない。

## 自由な道路網に対応する構成

- `MapDefinition.cs`: 地点・道路のScriptableObjectデータ。
- `MapManager.cs`: 地点／道路IDの索引、接続確認、1本ごとの時間、地図クリック判定、ルート表示、ズーム・移動。
- `MapEdge.cs`: 始点・終点・距離・道路種類・交通量係数・双方向フラグ。
  `Bidirectional=false`ならNodeA→NodeBだけ通行可能。
- `ManualDeliveryRoute.cs`: 道路IDと地点IDを順番に記録。接続チェック、往復、Undo、全消去、訪問確認、完了可否を管理。
- `RoadPathfinder.cs`: 任意のIDと接続を持つ道路網から推奨経路を探索する。
- `DeliveryPlan.cs`: 完了するルートと対象注文のスナップショット。画面上の候補プランではなく内部の完了データ。
- `DeliveryPlannerUI.cs`: Play開始時に操作画面を生成し、注文・配達員の既存Prefabを接続。
- `DeliveryFlowController.cs`: 作成したルートが全対象配達先を訪問して店舗へ帰還済みの場合だけ完了・加点。
- `Assets/Editor/M3Validation.cs`: 検証メニュー。

道路・地点を増やす場合は、Projectビューの `Create > Pizza Delivery > Road Map` でデータを作り、
MapRootのMapManagerの `Map Definition` に割り当てる。指定がなければ現在の5地点のサンプルを使う。
地点IDは任意で、店舗はIsStore=trueの地点を1件設定する。各道路は存在する地点を接続し、IDを重複させない。
注文のDestinationNodeIdを新しい地点IDに合わせる。
手動ルート・経路探索にはGoal1/Goal2専用の分岐を設けていない。

## 計算

通常: `距離 / (baseSpeed * TrafficFactor)`

裏道: `通常時間 * (1 + (1 - SkillLevel) * backstreetPenalty)`

通った道を順番に足す。同じ道を2回通れば2回分を計上する。
往路・復路で別々の道を使える。途中でGoal1を通り直しても注文の再加算はしない。
配達員変更では描いたルートを保持し、スキルによる時間を再計算する。
注文変更ではルートを消して、対象配達先の食い違いを防ぐ。

初期設定の推奨例（注文2件）:

- Minato（Skill 0.9）: 裏道を使うルートで約6.86秒。
- Ren（Skill 0.3）: 大通りを使うルートで約7.33秒。
- プレイヤーは推奨と異なる道を選んでもよい。

## 検証結果

Unity Editor 6000.2.10f1でコンパイルエラー・警告なし。

- 接続／非接続、往復、Undo、置換の失敗時保持、店舗帰還、未訪問チェック、スキル、推奨適用・編集、
  別の地点名のグラフ、一方通行、並行する道路、到達不能などの自動チェック41項目が合格。
- 地図クリックと同じ入力処理で、裏道と大通りの選び分けを確認。
- 手動で裏道を往路に使い、Goal1経由・大通りで帰る別経路を作り、約7.20秒になることを確認。
- 配達員をRenへ変えても道順は変わらず、約7.98秒へ再計算されることを確認。
- 手動ルートを完了ボタンの実クリックで確定し、注文2件削除・200点・選択／ルート解除を確認。
- 二重完了の再加点なし、直近の実行時エラーなし。
- UIで個別参考時間、短縮、同時間、遅延、未完成ルートの比較保留を確認。
- 完了後とルート画面更新後の比較結果保持、新しい注文選択時の前回結果解除を確認。
- 1件配達の参考時間6.36秒・同時間表示・100点、2件配達の参考時間14.07秒・6.73秒短縮・200点を確認。

計算とルートのチェックはPlay中に `Tools > Pizza Delivery > Validate M3 Sample (Play Mode)` から再実行可能。
基準速度10・ペナルティ係数1・標準のサンプル道路データを前提とする。
