# 設計書・計画書: マップの自動生成と複雑化(+ 商品の多様化との関係)

> 作成: 2026-10-23。ユーザーの決定: **ピザの種類(S2-6)とマップの自動生成・複雑化は、両方やる**(品質を担保するため)。
> マップは**完全ランダムにしない**(変なマップが出たときの対処が難しい)。**ある程度ランダムで、ゲームに支障がない**こと。**日数が経つと、マップが変わる**こと。

## 1. 狙い

| 狙い | 中身 |
|---|---|
| 繰り返し遊べる | 新しいゲームを始めるたびに、街が少し違う(同じシードなら同じ街) |
| 成長を感じる | 日数が進むと、街が広がり、道が増え、判断が難しくなる(配達の悩みが深まる) |
| 品質を保証する | どんな街が生成されても、**必ず遊べる**(到達できる、裏道に価値がある、極端に偏らない)。生成の結果を**自動で検査**し、不合格は捨てる |

## 2. 方針(決めたこと)

1. **「手作りの部品」を「ルール付きで組み合わせる」方式**にする。完全に自由な生成(ノイズや迷路)はしない
   - 街を**街区(ブロック)**の格子として扱う。街区の種類(住宅街・商店街・公園・川沿い・団地など)は**手で作ったテンプレート**から選ぶ
   - ランダムは、**どのテンプレートを選ぶか・向き・道の太さの割り当て・一方通行や工事の位置・注文が発生しやすい家**に限る
2. **すべての生成結果を、自動で検査**する(3章)。不合格は**作り直し**(最大N回)。N回とも不合格なら、**手作りの「安全な街」**(フォールバック)を使う。→ 「変なマップ」は出ない
3. **同じシードなら同じ街**(セーブにシードを保存)。バグの再現・自動プレイ・数値の比較ができる
4. **日数による変化は、「拡張」を基本**にする(4章)。既存の道は残す(土地勘を失わせない)
5. 既存の `MapDefinition` のデータ形式は**変えない**。生成器は、`MapDefinition` を**作る側**になる(ゲームのロジックは、これまでどおり読むだけ)

## 3. 生成の仕組み(案)

### 3-1. 流れ
```
シード
 ├─ ① 街区の格子(例: 5×4)を決める(中央に大通りを通す)
 ├─ ② 各街区に、テンプレートを割り当てる(隣り合わせのルールを守る)
 ├─ ③ 大通り・裏道・川と橋・一方通行・混雑しやすい道 を、ルールで決める
 ├─ ④ 店の位置と、配達先の候補(家・アパート)を置く
 ├─ ⑤ MapDefinition に変換
 └─ ⑥ 検査(合格なら完成 / 不合格なら ①へ戻る。最大N回。だめならフォールバック)
```

### 3-2. 検査(バリデータ)の項目(閾値は調整項目)
| 検査 | 内容 | 目的 |
|---|---|---|
| 連結性 | 店から、すべての配達先へ道でつながっている(一方通行も考慮した往復) | 行けない家を出さない |
| 孤立・行き止まり | 孤立した道がない。行き止まりの割合が上限以下 | 変な形を防ぐ |
| 裏道の価値 | 一定数の配達先で、**裏道の経路が、大通りの経路より速くなりうる**(速くなる差が下限以上、上限以下)。ただし、すべてが裏道有利ではない | ゲームの核(道を選ぶ判断)を保証 |
| 迂回の存在 | 大通りの混雑区間に、代替経路がある | 渋滞を回避する選択肢 |
| 規模 | 道の数・総延長・配達先の数が範囲内 | 重すぎ・軽すぎを防ぐ |
| 距離の分布 | 店から配達先までの距離が、近い・中・遠いに分かれている(偏りすぎない) | まとめ配達の面白さ |
| まとめ配達の余地 | 近い配達先の組(例: 2〜3件)が一定数ある | 「近くをまとめる」判断ができる |
| 橋・川 | 川を渡る道が2本以上(1本だと詰む) | 詰みを防ぐ |
| 一方通行 | 一方通行で、帰れない配達先がない | 帰還不能を防ぐ |
| 表示 | 道・名前札・ピンが重なりすぎない(最小間隔) | 地図の見やすさ |

### 3-3. フォールバック
- **手作りの安全な街**を、2〜3種類用意する(いま遊べているマップをベースにする)
- 生成が何度も不合格になったとき、またはバグで例外が出たとき、フォールバックを使い、**ログに記録**する

## 4. 日数による変化

2つの層に分ける。

### 4-1. 街の拡張(永続。数日ごと)
- 例: **開始時は小さい街(2〜3街区)**。**N日ごと**(または評判・日数の条件)に、**新しい街区が1つ増える**
- 既存の街区と道は**そのまま**(道のIDも変えない)。新しい街区は、**外側に追加**する。→ **土地勘**(配達員が道を覚えている)は維持され、新しい道は「知らない道」から始まる(成長の余地)
- 新しい街区は、**予告**する(精算画面で「あした、東の街区が開きます」)。注文の発生範囲も、広がる
- 拡張のたびに、検査(3章)を**全体に対して**通す。不合格なら別の街区を試す

### 4-2. 日替わりの変化(一時的。毎日)
- 例: **工事中**(一部の道が数日通れない・遅くなる)、**イベント**(混雑する道が変わる)、**天気**(任意。雨の日は裏道が遅い)
- 朝(店の画面)に、**今日の街の情報**を表示する(「駅前通りは工事中」)。→ 毎日のルート判断が変わる
- 変化は小さく、**検査を通す**(通行止めで孤立する配達先がない)

> **採らない案**: 数日ごとに街を**丸ごと作り直す**。土地勘が無意味になり、成長の手応えを壊すため。もし「違う街へ引っ越す」演出が欲しければ、**章の区切り**(例: 20日ごとの新しい街=新しいステージ)として、別に設計する。

### 4-3. 複雑さの段階(例。調整項目)
| 段階 | 日数の目安 | 街区 | 追加される要素 |
|---|---|---|---|
| 1 | 1〜5日 | 3街区 | 大通り、裏道 |
| 2 | 6〜10日 | 5街区 | 川と橋、一方通行 |
| 3 | 11〜20日 | 8街区 | 工事・イベント、団地(まとめ配達が増える) |
| 4 | 21日〜 | 12街区 | 複数の混雑パターン、遠い住宅街 |

## 5. 商品の多様化との関係(S2-6を必須にする)

- **ピザの種類**(`設計書_店内シーン.md` のS2-6)を**必須**にする。マルゲリータ・ペパロニ・シーフード(+ 後述の追加)
- 種類で、**工程の数・焼き時間・基本の得点**が変わる(調理の悩みが増える)
- マップの拡張と連動させる: 例: **新しい街区が開くと、新しい種類の注文が出る**(商店街ではシーフード、団地ではファミリー向けの大きなピザ)など。種類の解禁は、設備(メニュー拡張)と日数のどちらか(調整項目)
- 追加の候補(**S2-6の後、時間があれば**): サイドメニュー(ポテト・ドリンク)。注文に付いてくる(積載量は消費しないか、小さく消費する)。**まずはピザの種類だけ**
- 注文の発生(場所・種類)は、**街区ごとの傾向**(テンプレートに持たせる)で決める

## 6. 既存への影響

| 対象 | 変更 |
|---|---|
| `MapDefinition` | **形式は変えない**。生成器が作る。シードと拡張の段階をセーブに保存 |
| ルート・経路探索・土地勘 | 変更しない(読むだけ)。拡張時に、道のIDが変わらないことを保証 |
| 注文の発生 | 発生位置を、街区の傾向と、拡張範囲から決める(既存の発生ロジックを調べて、最小の変更で) |
| 地図の描画 | 生成した街を描く(S2-Mの区画描画・LOD)。街区のテンプレートに、絵の飾り(木・公園・川)の情報を持たせる |
| 自動プレイ・検証 | 多数のシードで、生成→検査→自動プレイ(数日)を回す。固定シードの回帰テストも追加 |
| 精算・店の画面 | 「あした街が広がる」予告、「今日の街の情報」の表示 |

## G-2: 検査・再試行・フォールバック

**仕様**: 3-2、3-3。

**指示文**

## 8. リスク

| リスク | 対処 |
|---|---|
| 変な街が生成される | 部品の組み合わせ+検査+再試行+フォールバック。1,000シードで検証。生成の結果をログに残す |
| 検査が厳しすぎて、毎回同じような街になる | 合格率とバリエーション(指標の分布)をG-2で測り、閾値を調整 |
| 検査が甘く、つまらない・詰む街が出る | 「必ず遊べる」の検査項目を増やす。自動プレイの完走を条件にする |
| 拡張で土地勘が壊れる | 道のIDを保つ。G-0で確認。同じシードで同じ街になる検証 |
| ゲームのバランスが崩れる(街が広がると、期限が厳しすぎる) | 目安時間の設定と合わせて、G-4で測る。数値の判断はユーザー |
| 作業量が大きい(店内シーン+商品+マップ+見た目) | 順番を守る(店内シーン → 商品 → マップ → 見た目)。各段階でコミットし、戻せるようにする。**最小の線**: G-0・G-1・G-2(生成と検査)を先に。G-3の日替わりの変化(工事)は後回しにできる |
| 地図ビューの性能(街が大きくなる) | S2-Mのチャンク描画・LODで対応。10倍の地図で測る(S2-0・S2-M) |

## 9. 未確定・遊んで決めること
- 街の拡張の間隔(N日)と、街区の最大数
- 日替わりの変化の種類(工事のみ / イベント・天気も)
- 章の区切り(20日ごとに新しい街へ)を入れるか
- 街区テンプレートの種類と、注文の傾向(種類の連動)
- サイドメニュー(S2-6の後)を入れるか
- 完全ランダムの街(ランダムモード)は、**入れない**(対処が難しいため)


## 追加変更（2026-10-23：住宅と裏道の見やすさ）

生成形式v4は1街区4軒を初期値とし、開始5街区＋既存2軒で22軒。密度と追加住宅の位置はInspectorで設定し、密度はセーブにも保存する。v3の既存街は、元の家・交差点・道・距離・方向をすべて維持できる場合だけ住宅を追加する。異なる街区進行を使うv1/v2は維持する。

裏道は接続点を保った折れ線として大通りから離して表示する。RoadGeometryを、道路の描画・クリック判定・ルート線・配達員の移動表示で共用する。表示上の長さを配達時間や道の距離に使わない。
