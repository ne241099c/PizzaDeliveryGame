# 設計書・計画書: 店内シーン(ピザ作りと配達を、1つの空間でつなぐ)

**狙い**: 営業中は画面を切り替えず、**1つの「店の中」**で、ピザを作る → 箱に入れる → 配達員に渡す → ルートを決めて送り出す、までを一続きの行為にする。
調理シミュレーターのように**物を直接つかんで動かす**。ただし、調理は**自分でやってもよいし、内勤(厨房スタッフ)を雇って任せてもよい**。任せれば、自分は配達の判断に集中できる。

決定事項(ユーザー確認済み): **2Dのトップダウン**。調理は**自分 or 内勤**。

実施の順番: **この設計書(S2-0〜S2-8) → 画面デザイン(`設計書_画面デザイン.md`)** の順に、一部を並行して進める(10章)。
ビルド・README(`計画書_ビルドとREADME.md`)は、これらが終わるまで**保留**する。

## 1. 今の問題と、作り直す理由

| 今 | 問題 |
|---|---|
| 営業画面が、地図・注文・配達員・計画パネルのパネルの集まり | 「ピザ屋を営む」感じがなく、操作がバラバラ |
| 調理は、待ち行列とゲージだけ(M7のC-1・C-2) | ピザを作っている感がない。何も触れない |
| 調理と配達が別々の処理 | 「作って、渡して、送り出す」の流れがない |

**再利用するもの(作り直さない)**: 注文の発生・期限・得点・評判・精算・セーブ・設備の費用、配達員の移動・事故・ルート作成のロジック(`ManualDeliveryRoute`、`RoadPathfinder`、`DeliveryPlannerUI`の中身)、調理の窯の台数と調理時間の設定。
**作り直すもの**: 営業画面の見た目と操作(S-3で作った配置)、調理の中身(待ち行列 → 工程と物)。

**指示盤(地図)の画面の決まり(改訂2: レーン方式)**
- 地図が主役。**画面全体を地図にし**、操作の部品は縁に小さく重ねる。厨房側から指示盤へのカメラのパンは残してよいが、着いた先は地図が全面
- 画面の下に、**配達員ごとの横長の「レーン」**を並べる(待機中は使える、配達中は灰色で「不在(あと◯秒)」)。レーンには**積載量ぶんのスロット**があり、積載量が成長するとスロットが増える
- 操作は**2手順**を手順バーで常に見せる(いまの手順は黄色、終えた手順は緑のチェック)。地図上に「いまここ」の吹き出し
  1. **伝票(注文リストの伝票、または地図のピン)を、配達員のレーンにドラッグ&ドロップ**。これで「組む」と「渡す」が1回で済む。同じレーンに複数入れると、まとめて運ぶ(=便)
  2. **ルートを直して、レーンの `出発`**。店→届け先…→店の往復の**自動ルート**が先に地図に出る。**ルートの線のハンドル(⇄)をドラッグして通る道を変える**。届け先の順番は、**レーンの伝票を並べ替える**
- **伝票を持ったとき**: 地図上で、**近い注文のピンが光り**(「近い・4秒」)、レーンには入れたときの**所要の目安**(例: まとめると約14秒、別々だと約20秒)を表示。入らないレーン(積載量いっぱい・不在)は置けず、理由を表示
- 厨房側で、箱を配達員の上に直接ドロップしてもよい(その配達員のレーンに1件入る。近道)
- 出す情報は最小限: 配達員の名前と状態、バッグ(n/最大)、行く順番、所要秒数と「速い/遅い」、お届け目安に間に合うか。**能力値・内訳・長い説明は出さない**(詳細は選択時のツールチップ)

## 3. 物を動かす仕組み(「手」)

- **つかむ**: 物をクリック(またはドラッグ開始)すると、**手に持つ**。持った物はカーソルに追従する(少し遅れて、影を付けて浮かせる)
- **置く**: 置ける場所の上でクリック(またはドラッグ終了)。置ける場所は**光る**。置けない場所では、元の位置に戻る
- **持ったまま、カメラを動かせる**(パンしても手の中身は残る)。持ったままQ・Eで厨房から指示盤へ移れる
- **取り消し**: 右クリックかEscで、元の場所へ戻す
- 持てるものは**1つだけ**(箱は、袋にまとめて渡すときだけ複数)
- 物の見た目は、重なり・影・置いたときの小さな弾み(0.1秒)で「触れている感」を出す(物理演算は使わない)
- キーボードだけでも操作できる補助(Tabで選択、Enterで置く)は、後で付ける(任意)

## 4. ピザを作る工程

### 工程(1枚のピザ)
| 順 | 工程 | 手動の操作 | 内勤に任せたとき | 品質への影響 |
|---|---|---|---|---|
| 1 | 生地 | 材料棚の生地をクリック → 作業台に置く(自動で丸く伸びる) | 自動 | なし |
| 2 | ソース | おたまをつかみ、生地の上を**なぞる**。塗れた割合が使われる | 自動 | 塗れた割合(70%未満は★減点) |
| 3 | チーズ | チーズの容器を生地の上に**ドロップ**(ふりかけの動き) | 自動 | なし(量は固定) |
| 4 | 具 | 注文の指定の具のトレイを生地の上に**ドロップ**(ペパロニなど、1〜2種) | 自動 | **指定どおりの具か**(間違えると★減点) |
| 5 | 焼く | ピザをピールに乗せ、**窯に入れる**。窯のゲージが帯に入ったら**取り出す** | 自動(帯の真ん中で取り出す) | 取り出しのタイミング(帯の中なら★up) |
| 6 | 梱包 | 保温棚のピザを**箱にドロップ** → 箱を**閉じる**(クリック)。伝票が自動で貼られる | 自動 | なし |

- 1枚あたりの手動の操作は **8回前後**(クリック・ドラッグ・ドロップ)。所要は **10〜14秒**が目安
- 具が1種なら具の工程は1回、2種なら2回
- **窯と作業台が資源**。台数が足りないと、順番待ちになる(設備で増やす)

### 時間(秒は現実の秒。すべて調整項目)
| 工程 | 手動(目安) | 内勤の自動(手際0.5のとき) |
|---|---|---|
| 生地 | 操作時間のみ | 1.0 |
| ソース | 操作時間のみ | 2.0 |
| チーズ・具 | 操作時間のみ | 3.0 |
| 焼く | 4.0(窯の時間) | 4.0 |
| 梱包 | 操作時間のみ | 2.0 |
| **合計** | **自分の腕しだい(約10〜14)** | **約12**(M7の `cookSeconds` と同じ) |

- 窯の時間は、手動でも内勤でも**同じ**(窯は窯)。他の工程は、**手際**で内勤の速さが変わる(手際が高いほど速い。`時間 ×(1.3 − 0.6×手際)`)
- **自動プレイと、お届け目安の下限**は、内勤の自動(約12秒)を基準にする(M7の調整がそのまま使える)

### 品質(★1〜3)
- 工程ごとの出来から点を集める: **ソース**(70%以上=1点)、**具**(指定どおり=1点)、**焼き**(帯の中=1点)。合計 0点 → ★1、1〜2点 → ★2、3点 → ★3
- 内勤の場合は、各工程の点を**丁寧さ**で確率的に決める(丁寧さ0.5なら各工程の成功が約50%+)。★1になったら、自動で作り直す(下の「失敗と作り直し」)
- 品質の効果:

| 品質 | 得点ボーナス(期限内のみ) | 評判 |
|---|---|---|
| ★1 | 0 | 変化なし |
| ★2 | +15 | 変化なし |
| ★3 | +40 | +0.5 |

> M7の「完璧ボーナス +15」は、この品質ボーナスに置き換える(焼きの帯=1点として吸収)。

### 失敗と作り直し(改訂 2026-10-23。承認モック `UI_Mock/Redo.png`)
**方針(ユーザー決定)**: 失敗しても**配達はできる**(焦げは★1で配達可。違う具でも客は受け取る)。**直すかどうかは、プレイヤーが決める**(期限と材料費・時間の相談)。

| ミス | 結果 | 取り返し |
|---|---|---|
| 軽い(ソースが薄い、焼きのずれ) | そのまま配達可。点が入らず★が下がる | 作り直してもよい |
| 生焼け(早く取り出した) | 窯に**戻して続きを焼ける** | 時間のロスだけ |
| 焼きすぎ(帯の後〜焦げ手前) | 配達可。焼きの点なし | 作り直してもよい |
| **焦げ**(帯を過ぎて+5秒) | **★1固定で配達可**。見た目も焦げ | 作り直してもよい |
| **違う具**(伝票と合わない) | **客は受け取る**。具の点なし(★が下がる)。梱包のとき**警告**が出る | 作り直してもよい |

**作り直しのUI**
1. **失敗に気づく**: 焼き上がり・梱包の直後に、ピザの横に**ふきだし**(ミスの内容、「このまま出す」「捨てて、作り直す」の2ボタン)。選ばなければ、そのまま台に残る。違う具は、梱包のとき伝票と照合して同じふきだしを出す
2. **捨てる**: ピザを**ゴミ箱**にドラッグ(ゴミ箱は光る)。ふきだしのボタンでも同じ。取り消しは右クリックかEsc。廃棄すると**材料費がかかる**(`wasteCost`、初期値20=その枚数の材料費)
3. **作り直す**: 同じ伝票が、**「作り直し」の札**つきでレールに残る。作業台に新しい生地が出る。**期限は進み続ける**(待ってくれない)
4. **内勤は、優先して作り直す**: 内勤が作ったピザが**★1(0点)**になったら、**期限に余裕があれば、自動で廃棄して作り直す**。作り直しの伝票は、内勤の**待ち行列の先頭(最優先)**に入る。期限に余裕がない(残り時間 < 作り直しの所要+配達の最短所要。`redoMinRemainingSec`)ときは、そのまま出す。★2は作り直さない(`redoBelowStar` 初期値2=★1のみ。調整項目)。プレイヤーがふきだしで「このまま出す」を選んだ伝票には、内勤は手を出さない。内勤の廃棄の材料費は、店が負担し、精算の廃棄に計上する
- ゴミ箱は、厨房の作業台の近くに1つ。廃棄した枚数と損失額は、**精算に表示**する
- 判断の中身: 作り直す=材料費+約12秒で、うまくいけば★2〜3のボーナスと評判。出す=すぐ届くが★1。**期限が近いなら出す**のが手

## 5. 内勤(厨房スタッフ)

- 配達員とは**別の職種**。求人に「内勤」の候補が出る。雇用・解雇・日給・採用費は、配達員と同じ仕組み(`RecruitmentManager`)
- 能力は2つ(0〜1): **手際**(工程の速さ)、**丁寧さ**(品質)
- 日給: `40 + 50 × (手際 + 丁寧さ)`(調整項目)。例: 手際0.5・丁寧さ0.5 → 90
- **名簿の上限(初期4)は、配達員と内勤の合計**。人数の取り合いが判断になる(店舗拡張で増える)
- 開始時の名簿: 配達員2人(Aoi、Ren)+ **内勤1人(見習い)**。内勤を外せば、自分で全部作る(自由)
- **担当の割り当て**:
  - 伝票は、**既定では内勤に自動で回る**(空いている内勤がいて、作業台・窯が空いていれば)
  - **自分でやる**: 伝票を**つかんで、作業台に置く**と、その注文は自分が作る(内勤は取らない)
  - 内勤が手一杯、または内勤がいなければ、伝票は待つ(自分が取ってもよい)
- 内勤の見た目: 作業台・窯のそばに、キャラ(丸いアイコン+頭文字)が立ち、作業中は動く(手元のゲージ)
- 成長(経験・訓練)は、**後回し**(M8以降)。まずは能力を固定にする
- 内勤は、作業台・窯を**配達員の人数とは関係なく**使う(作業台1台につき内勤1人)。設備で作業台を増やせる(S2-4)

## 6. 配達との接続(シームレスな部分)

### 流れ(改訂2: 配達員のレーンに伝票をドロップ)
1. 焼き上がり → 梱包 → **箱(伝票つき)**ができる。**受け渡し**の台に置かれる(最大6個)。注文リストにも出る
2. **①レーンに入れる**: 伝票(リストか地図のピン)を、**待機中の配達員のレーン**にドロップ。レーンの積載量(スロット)まで入る。入れた瞬間に、その配達員の袋に箱が入る。伝票を持っている間は、近い注文が地図上で光り、レーンに所要の目安が出る
3. **②ルートを直して出発**: レーンに伝票が入ると、地図に**自動ルート(灰・点線)**と**あなたのルート(赤)**が出る(最初は同じ)。**⇄ハンドルをドラッグして通る道を変える**。レーンの伝票を並べ替えると訪問順が変わる。所要と、**自動ルートとの差**を表示。`出発` / `自動に戻す`
4. 出発。配達員がレーンから消え(「不在」)、地図上を動き始める(材料費20/件は出発時に払う。従来どおり)
5. 配達中は、指示盤で動きを見る。**別の区画にいても**、到着・事故・帰還は通知される
6. 帰還した配達員は、レーンが使えるようになる(体力の回復が始まる)
- **戻す**: レーンの伝票を、リストへドラッグで戻せる(出発前なら、材料費は不要)
- **複数の配達員のレーンを、同時に組める**(忙しいときに、2人ぶんを並べて組める)

### 使いやすさの工夫(人の操作の観点。遊んで調整)
1. 「便」という言葉は画面に出さない(配達員のレーン=まとめて運ぶ荷物)
2. **待機が1人だけのとき**: その配達員のレーンを、最初から目立たせる(ドロップ先を迷わない)。複数のときは、おすすめの人(近さ・体力・土地勘)に印を付ける
3. 手順バーの前の手順をクリックで戻れる(入れた伝票は消えない)
4. 近道: 厨房側で、箱を配達員の上にドロップすると、その配達員のレーンに1件入る
5. 初回だけ、吹き出しで操作を説明する(「伝票をレーンへ」「⇄をドラッグ」)

> **自動ルートは、わざと素直な案**にする(最短距離で、混雑・土地勘を考えない)。プレイヤーが、混雑や裏道を考えて直すと、所要が縮む、という遊びの核を残す。既存の `RoadPathfinder` の結果を、自動ルートとして使う(変更しない)

### バッグの大きさ(一度に運べる数)の成長
- 既存の**積載量**(能力。訓練・成長で上がる)が、バッグの大きさ。バッグには**空きスロット(点線の「+」)**を並べ、まだ使えない段階は点線のまま見せる
- 成長の道筋を、配達員カードに1行で示す(例: 「積載量 3 → 4(トレーニング ¥380)」)
- 上限と費用の曲線は、**S2-0で現状(上限・訓練費・設備)を調べて報告**させ、私が決める。目安: 一度に運べる数が増えるほど、ルートの組み合わせ(まとめ配達)の面白さが増える。ただし、地図と目安時間の調整が必要
- 設備の候補(任意): 「大きなバッグ」(全員の積載量+1。費用・維持費は調整項目)

### 配達員の選び方
- 既存どおり、**待機中**の配達員だけ受け取れる(配達中・帰還中は、カウンターに「不在」の札)

### 箱が溜まったとき
- 受け渡しの台に置ける箱は **6個まで**。それ以上は、梱包できない(焼き上がりが保温棚に溜まる)
- 期限が切れた注文は、箱もピザも**キャンセル**になり、片付けられる(従来のキャンセル規則)

## 8. 実装の方針(技術)

| 方針 | 理由 |
|---|---|
| 店内は**ワールド空間の2D**(SpriteRenderer+Collider2D)。HUDはCanvas(オーバーレイ) | 物を動かす・当たり判定にはワールド空間が向く。HUDは既存のUIの資産を使う |
| `HandController`(手)を作る。つかむ・置く・戻す、ドロップ先の判定(`Collider2D` の `IDropTarget`)を担う | 物の動かし方を一か所にまとめる |
| 区画ごとに `Zone` を作り、カメラは `ShopCameraRig` が管理(パン・全体表示・通知) | 「画面の切り替え」ではなく「カメラの移動」にする |
| ピザは `PizzaItem`(状態、品質、注文ID、見た目の層)。工程は `PizzaStage` の状態機械。手動と内勤は、**同じ状態機械を別の「作り手」が動かす**(`IPizzaWorker`: Player / Staff) | 手動と自動で、ルールが食い違わないようにする。検証もしやすい |
| 指示盤は、**地図を画面全体に表示する地図ビュー**にする(既存の `MapViewportUI` などを拡張。方式はS2-0で選ぶ)。既存の操作を壊さない | 地図・ルート作成のロジックを再利用する |
| 画面の非表示は CanvasGroup(既存方針)。Canvasの子の並びに依存する処理に注意 | M5-2・S-1の教訓 |
| 数値はすべて `[SerializeField]`(Inspector) | 既存方針 |

### 地図ビューの要件(大きな地図でも動く)
- **見た目と操作はGoogleマップ風**: ドラッグで移動、ホイール(ピンチ)でズーム(カーソル位置が中心)、+/−ボタン、現在地(店)へ戻る、ミニマップ(見えている範囲の枠つき)、混雑レイヤーの切り替え
- **大きな地図でも軽く**: 地図を**固定サイズの区画(チャンク)**に分けて描き、**画面に映る区画だけ**を描画する(視錐台カリング)。区画の絵は、必要になったときに生成してキャッシュ。ズーム段階(LOD)ごとに、道の太さ・名前札・小さな建物の表示を切り替える(遠いときは大通りと主な地名だけ)
- ピン・ルート・配達員の印は、ズームしても**画面上の大きさを保つ**(最小16px)。ピンが密集したときは、ズームアウト時にまとめて数字で表示
- 目標: 現在の地図の10倍の道の数でも、60fpsを保てる設計にする(実測はS2-0・S2-Mで)。`MapDefinition` のデータ形式は変えない
- 地図の描画は**データから自動**(街区・建物・道・名前札)。手で置く飾りは別の層

> **指示盤の実装**は一番難しい。地図は現在UGUIなので、(a) 指示盤の区画だけUGUIを重ねる(区画に合わせて位置を追従)、または (b) 地図をワールド空間に移す、の2案。**S2-0で調査して、案を選んで報告**させる(判断は私が行う)。

## S2-3: 調理の工程と品質(手動)

**仕様**: 4章。
- `PizzaItem`(状態、品質の点、注文ID、見た目の層)と、工程の状態機械(`PizzaStage`: 生地 → ソース → チーズ → 具 → 焼く → 梱包)
- 手動の操作: 生地を作業台へ、おたまでなぞる(塗れた割合)、チーズのドロップ、具のトレイのドロップ(指定の具か)、ピザを窯へ、窯の帯で取り出す(焦げは帯+5秒)、保温棚から箱へ、箱を閉じる
- 品質(★1〜3)と、得点ボーナス(★2 +15、★3 +40、期限内のみ。作り直しの損(材料費20+約12秒)より大きくする)・評判(★3で +0.5)。精算に内訳(品質ボーナス)を追加
- 窯・作業台は**資源**(使用中は他で使えない)
- 「自分でやる」: 伝票を作業台にドロップして、その注文を作り始める
- **M7のC-2の完璧ボーナス(+15)は、この品質ボーナスに置き換える**(窯の帯=1点として吸収)
- 注文の状態に `梱包済み` を追加。期限切れで、ピザと箱をキャンセル(片付け)
- **失敗と作り直し**(`失敗と作り直し` の章。承認モック `UI_Mock/Redo.png`): 焦げは★1で配達可。違う具は客が受け取る(梱包のとき伝票と照合して警告)。ミスしたピザの横にふきだし(「このまま出す」「捨てて、作り直す」)。ピザをゴミ箱へドラッグして廃棄(材料費がかかる)。同じ伝票に「作り直し」の札。生焼けは窯に戻せる。廃棄枚数と損失額を精算に表示

**完了条件**: 生地から梱包まで、自分の手で作れる。品質が工程の出来から決まり、★に応じてボーナスが入る。焦げが起こる。期限切れで片付く。既存の全検証と新しい検証が通る。

**指示文**

## S2-4: 内勤

**仕様**: 5章。
- 内勤(`KitchenStaff`: 手際、丁寧さ)。求人に内勤の候補が出る。雇用・解雇・日給(`40 + 50×(手際+丁寧さ)`)・採用費・解雇手当は配達員と同じ仕組み

- 割り当て: 既定は内勤に自動で回る。自分で作りたい伝票は、作業台へ持っていけば自分の担当になる
- **作り直し**: 内勤が作ったピザが★1(0点)になったら、期限に余裕があれば自動で廃棄して作り直す。作り直し伝票は、内勤の待ち行列の**先頭(最優先)**。余裕がない(残り < 作り直しの所要+配達の最短所要)ときはそのまま出す。★2は作り直さない(閾値は調整項目)。プレイヤーが「このまま出す」を選んだ伝票には働かない。廃棄の材料費は店の負担で、精算に計上
- **作業台の増設**(設備: 1→2→3台、400 / 700、維持費 +15/日)
- 店の画面(スタッフ・求人)に、内勤を表示(カードの種類を区別)

**完了条件**: 内勤がいれば、自分が何もしなくても、ピザが作られて保温棚に出る。内勤がいなければ、自分で作る。自分の担当にした伝票は、内勤が取らない。日給・採用費・セーブが正しい。既存の全検証と新しい検証が通る。

| 品質・ボーナス・日給の数値で、バランスが崩れる | 調整項目にして、S2-7で測る。人が遊んで判断 |
| 見た目(絵)が間に合わない | まず色の四角で作り、あとから絵を差し替えられる構造にする(`設計書_画面デザイン.md`) |
| 配達の判断が、調理の忙しさに押されて、ゲームの核が薄れる | 内勤を雇えば、配達に集中できる。遊んで、調理と配達の重みを調整 |

## 12. 未確定・遊んで決めること
- 手動調理の操作数と、ソースのなぞり方(円か、クリックか)
- 内勤の初期人数(いまは1人)と日給
- 品質ボーナスの額(+15 / +40。作り直しの損と釣り合うか、S2-7で測る)、焦げの猶予(+5秒)
- 内勤の成長(経験・訓練)を入れるか(いまは後回し)
- ピザの種類(S2-6)を入れるか
- キーボードだけの操作の補助
- 配達員にも、店内で動くアニメーション(出入り)を付けるか(S2-8)

## 追加変更（2026-10-23：配達・厨房の操作改善）

- スタッフ一覧と配達レーンは、ホイール・背景ドラッグ・横スクロールバーで移動する。荷物のドラッグと、空カードのスクロールを分ける。

- 帰還待ちは残り秒数と進捗ゲージを表示する。ゲージは事故による到着予定の変更も反映する。出発前の比較は事故前の予測時間のまま。
- 家の注文ピンは、待ち＝黄、作り中＝青、焼き中＝赤、焼き上がり＝緑。注文のない家は建物だけを表示する。注文番号は高コントラストで表示する。
- 窯の共通FIFOキューに、待っているピザと注文番号を表示する。
- 廃棄の費用は0。注文の期限は作り直しても延長しない。
- イカの表示はUITheme.squidToppingScaleで縮小する。
- 配達速度倍率はMapManagerのInspectorで1.6（直前の1.2に対し約1.33倍）。
