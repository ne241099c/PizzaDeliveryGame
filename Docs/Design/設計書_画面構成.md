# 設計書・計画書: 画面構成の再編(ゲームらしい画面遷移)

いまは1画面に、地図・注文・配達員・準備・精算が同居している。これを、**場面ごとに画面を分け、「次に何をするか」が一目で分かる流れ**にする。
**ゲームのロジックは変えない。** 既存の部品(OrderListUI、DeliveryPlannerUI、PreparationUI、CampaignManager など)を、新しい画面へ**移す**作業が中心。

実施の順番: M6調整 → **この画面構成(S-0〜S-5)** → 見た目の底上げ(`Archive/計画書_見た目.md`)。見た目を整える前に、器となる画面を決めておく(画面ごとに二度作らないため)。

## 1. なぜ分けるか

| 問題(いま) | 分けた後 |
|---|---|
| 何を見て何を押せばよいか分からない(情報が全部同時にある) | その場面で必要なものだけが出る |
| 準備・営業・精算が同じ見た目で、1日の区切りが感じられない | 画面が変わり、「開店」「閉店」の気分が出る |
| 地図が小さい(ゲームの核なのに) | 営業画面では地図が主役になる |
| 配達の計画(ルート作り)が、他の情報に埋もれる | 計画のときは地図に集中できる専用の状態になる |
| 見た目を整えても、情報量が多すぎて整わない | 画面ごとに整えられる |

## 2. 画面の流れ

```
[タイトル] ──続きから/最初から──▶ [店(開店準備)] ──営業開始──▶ [営業]
                                     ▲                          │ 閉店・全員帰還
                                     │                          ▼
                                     └────次の日へ────── [精算(今日のまとめ)]
                                                                 │ 破産
                                                                 ▼
                                                            [ゲームオーバー] ──▶ [タイトル]
   どの画面からでも: [遊び方](重ねて表示) / [メニュー](Escで重ねて表示: 再開・タイトルへ)
```

- 画面の切り替えは、**CampaignManager の「日の段階」(開店準備 / 営業 / 精算 / ゲームオーバー)に連動**させる。段階が変われば、画面が変わる
- 切り替えには短いフェード(0.3秒)を付ける

## 3. 各画面の中身(1920×1080 を基準にした配置案)

### 3-1. タイトル
- ゲーム名、ボタン: `続きから`(セーブがあるとき)/ `最初から` / `遊び方` / `終了`
- 背景: 地図の簡単な絵(のちに見た目の底上げで整える)
- 仕様は M6-5 のセーブ選択を、ここに移す

### 3-2. 店(開店準備)— 拠点の画面
```
┌───────────────────────────────────────────────────────────┐
│ 3日目   所持金 ¥1,240 ▲   評判 ★72                   [メニュー] │ 上の帯(常に見える)
├──────────┬────────────────────────────────────────────────┤
│ ▶スタッフ │                                                │
│  求人     │   (選んだタブの中身)                             │
│  経営     │                                                │
│          │                                                │
│          ├────────────────────────────────────────────────┤
│          │ 今日の見通し:  固定費 ¥200 / 日給 ¥404 …  [営業開始 ▶] │
└──────────┴────────────────────────────────────────────────┘
```
- **スタッフ**タブ: 配達員のカード(丸のアイコン、名前、6能力のバーと素質の目印、日給、状態)を並べる。カード内に `訓練`(能力を選ぶ小さなダイアログ)と `解雇`
- **求人**タブ: 候補のカード(タイプの名前、得意な能力、能力と素質、採用費)。`雇う`
- **経営**タブ: お届け目安時間の設定、昨日までの記録(日ごとの損益の一覧か簡単なグラフ)、通算の記録
- 下の帯: 今日の見通し(固定費、日給の合計、所持金で足りるか)と、**大きな `営業開始` ボタン**(右下。一番目立たせる)
- 上の帯の数字は、営業・精算でも同じ位置に出して、画面が変わっても目が迷わないようにする

### 3-3. 営業 — 地図が主役
```
┌───────────────────────────────────────────────────────────┐
│ 残り 2:15 ▓▓▓▓░░   本日の売上 ¥640   評判 ★72   目安 60秒 [−][+] │ 上の帯
├────────┬──────────────────────────────────────┬───────────┤
│ 注文    │                                      │ (配達計画の  │
│ ┌────┐ │                                      │  パネル)    │
│ │田中│ │              地  図                    │  選択時だけ  │
│ │▓▓░ │ │                                      │  右から出る  │
│ └────┘ │                                      │           │
│ …       │                                      │           │
├────────┴──────────────────────────────────────┴───────────┤
│ [Aoi 待機 体力▓▓▓] [Ren 配達中 …] [Minato 訓練中 あと40秒]    │ 配達員の帯
└───────────────────────────────────────────────────────────┘
```
- **地図を画面の中心・最大**にする(周囲の帯は薄く)
- 左: 注文のカード(客名、届け先、期限の帯)。選ぶと2件まで選択できる
- 下: 配達員のカード(状態、体力)。待機中の人を選ぶ
- **配達計画パネル(右)**: 注文と配達員を選ぶと右から出る。ルートの作成(道を1本ずつ選ぶ)、個別配達との比較(`Individual reference`)、`出発` と `推奨経路で出発`。出発したら閉じる。選択を外しても閉じる
- **計画モード**: パネルが開いている間、地図を少し拡大・他の帯を少し暗くして、ルート作りに集中できるようにする(時間は止めない=リアルタイムの緊張感は残す)
- 上の帯の目安時間は、営業中にいつでも変えられる(既存仕様)

### 3-4. 精算(今日のまとめ)— 順に見せる
- 1ページにすべてを詰めず、**段階を追って表示**する(クリックかタイマーで次へ。`スキップ`もある):
  1. **売上**(配達件数、チップ)
  2. **コスト**(材料費・燃料費・日給・固定費の内訳)
  3. **今日の損益**(大きく。黒字は緑、赤字は赤)と、所持金の変化
  4. **成長**(誰の何が上がったか)・**評判の変化**
  5. `次の日へ` ボタン(破産なら `ゲームオーバー` へ)
- 全項目を一覧で見たい人のために、`まとめて表示` も置く

### 3-5. ゲームオーバー
- 到達した日数、通算の売上、最高日の売上、育てた配達員(能力の一覧)。`もう一度` と `タイトルへ`

### 3-6. 重ねて出すもの
- **遊び方**: 画像とテキストの数ページ(最初は文字だけ。のちに整える)
- **メニュー**(Esc): `再開` / `遊び方` / `タイトルへ`(営業中は、進行が失われる確認を出す)

## 4. 実装の方針

| 方針 | 理由 |
|---|---|
| `ScreenRouter`(画面の管理役)を作る。画面の種類(enum)ごとに、**1つのルート(CanvasGroup)**を持つ | 画面切り替えを1か所で管理する |
| **非表示は `SetActive(false)` ではなく、CanvasGroup(alpha=0, interactable=false, blocksRaycasts=false)で行う** | 既存の検証(337項目+M6)が、名前でオブジェクトを探している。非アクティブにすると見つからなくなる恐れがある |
| 画面は、CampaignManagerの段階が変わるイベントを購読して切り替える。ルーターがロジックを持たない | ロジックと見た目の分離を保つ |
| 既存の部品は**作り直さず、親を付け替える**(Transformの移動) | ロジックの検証を壊さないため |
| Canvasの子の並びに依存する処理を、最初に洗い出す(M5-2の教訓) | 並びを変えると既存検証が壊れる前例がある |
| 1つの `Canvas` に全画面を入れる(画面ごとにCanvasを分けない) | 参照が簡単で、既存の構造に近い |

## 5. 全体像(タスク)

| # | タスク | 規模 | 完了の目安 |
|---|---|---|---|
| S-0 | 現状調査 | 小 | 既存UIの部品が、どの新画面に属すかの対応表。検証が依存する名前・並びの一覧。before画像 |
| S-1 | ScreenRouter と画面の枠 | 中 | 段階に連動して画面が切り替わる(中身は既存の部品を移したもの) |
| S-2 | 店(開店準備)の画面 | 大 | スタッフ・求人・経営のタブ。営業開始ボタン |
| S-3 | 営業の画面 | 大 | 地図が主役。計画パネル。上の帯・注文・配達員の帯 |
| S-4 | 精算・ゲームオーバー | 中 | 順に見せる精算。ゲームオーバー画面 |
| S-5 | タイトル・遊び方・メニュー | 中 | タイトルから始まり、Escでメニューが出る |

ブランチは `m6` を `main` に統合した後、`main` から `screens` を作る。段階ごとにローカルでコミット。

### どのタスクにも共通の依頼
> ゲームのロジックは変更せず、画面の構成だけを変更してください。既存の部品は作り直さず、親の付け替えと配置の変更で新しい画面に移してください。画面の非表示は SetActive ではなく CanvasGroup で行い、既存の検証(M3〜M6)がすべて通ることを確認してください。Canvasの子の並びに依存する処理は、先に洗い出してください。
> 各段階の終わりに全検証が通ることを確認して、その段階だけを `screens` ブランチへローカルでコミットしてください(pushはしない。Packages変更、`.DS_Store`、`.codex`、`_Recovery` は含めない)。通らなければそこで止めて、原因を報告してください。判断した点は最後の報告にまとめてください。

## S-1: ScreenRouter と画面の枠

**仕様**
- `ScreenRouter` を作る。画面の種類(Title / Hub / Business / Settlement / GameOver)ごとに CanvasGroup のルートを持つ。`Show(screenId)` で切り替え(フェード0.3秒)
- CampaignManager の段階の変化(開店準備→営業→精算→ゲームオーバー)で切り替わる
- 既存の部品を、S-0 の対応表どおりに、新しい画面のルートへ親付け替えする。**中身の見た目はまだ変えない**(配置は仮でよい)
- 遊び方・メニューは、後の S-5 で作る

**完了条件**: 開店準備→営業→精算→次の日 の流れで、画面が切り替わる。既存の操作が、画面が分かれた状態でも動く。全検証が通る。

**指示文**
> `ScreenRouter` を作ってください。画面の種類(Title / Hub / Business / Settlement / GameOver)ごとに CanvasGroup のルートを持ち、`Show` で0.3秒のフェードで切り替えます。非表示は CanvasGroup(alpha=0、interactable=false、blocksRaycasts=false)で行い、SetActive は使わないでください。CampaignManager の段階が変わったときに、対応する画面へ切り替わるようにしてください(ルーターにロジックを持たせないでください)。S-0 の対応表どおりに既存の部品を新しい画面のルートへ付け替えてください(まだ見た目は変えず、配置は仮で構いません)。既存の操作が動くこと、全検証が通ることを確認してください。

**学べること**: 画面遷移の仕組み(ステートに連動する画面管理)。CanvasGroup。

## S-2: 店(開店準備)の画面

- スタッフのカードに、訓練と解雇を入れる(訓練は能力を選ぶダイアログ)
- 求人のカードに、タイプ・得意・能力と素質・採用費・雇うボタン
- 経営タブ: お届け目安時間、昨日までの記録の一覧
- **営業開始**を、右下に大きく

**完了条件**: 店の画面だけで、雇用・解雇・訓練・目安の設定・営業開始ができる。拒否の理由が表示される。全検証が通る。

**指示文**
> 店(開店準備)の画面を、`設計書_画面構成.md` の3-2のとおりに作ってください。上の帯(日数・所持金・評判・メニュー)、左のタブ(スタッフ・求人・経営)、中のコンテンツ、下の帯(今日の見通しと、右下に大きな営業開始ボタン)を配置します。スタッフのカードに、6能力のバーと素質の目印、日給、状態、訓練(能力を選ぶダイアログ)、解雇を入れてください。求人のカードに、タイプ名、得意な能力、能力と素質、採用費、雇うボタンを入れてください。経営タブには、お届け目安時間の設定と、日ごとの記録の一覧を入れてください。既存の PreparationUI などは作り直さず、配置を変えて移してください。拒否の理由の表示を維持してください。

## S-3: 営業の画面

**仕様**: 3-3のとおり。
- 上の帯(残り時間の帯、本日の売上、評判、目安時間の増減ボタン)、左の注文カード、下の配達員カード、中央の大きな地図
- 右の配達計画パネル: 注文と配達員を選ぶと右から出て、ルート作成・個別配達との比較・出発を行う。出発または選択解除で閉じる
- 計画モード: パネルが開いている間、地図を拡大し、周囲を少し暗くする。時間は止めない
- 地図の拡大・移動(既存)は維持する

**完了条件**: 営業中の操作(注文と配達員の選択、ルート作成、出発、推奨経路で出発、目安の変更)が、新しい配置で行える。地図が画面の大半を占める。全検証が通る。

**指示文**
> 営業の画面を、`設計書_画面構成.md` の3-3のとおりに作ってください。中央に地図を大きく置き、上の帯(残り時間の帯、本日の売上、評判、目安時間の増減ボタン)、左に注文のカード(客名、届け先、期限の帯)、下に配達員のカード(状態、体力)を配置してください。注文と配達員を選ぶと、右から配達計画パネルが出て、ルート作成、個別配達との比較、出発、推奨経路で出発ができるようにしてください。出発または選択解除で閉じてください。パネルが開いている間は、地図を少し拡大し、周囲の帯を少し暗くしてください(時間は止めない)。既存の DeliveryPlannerUI などは作り直さず、配置の変更で移してください。地図の拡大・移動は維持してください。

## S-4: 精算・ゲームオーバー

**仕様**: 3-4、3-5のとおり。
- 精算は、売上 → コスト → 損益 → 成長・評判 → 次へ の順に、クリックかタイマー(1.0秒)で表示する。`スキップ` と `まとめて表示` がある
- 破産のときは、最後のページが `ゲームオーバー` へ進む
- ゲームオーバー画面: 到達した日数、通算の売上、最高日の売上、配達員の一覧。`もう一度` と `タイトルへ`(タイトルは S-5 まで仮)

**完了条件**: 精算を順に見られ、スキップできる。数字は既存の精算の結果と一致する。破産でゲームオーバー画面へ進む。全検証が通る。

**指示文**
> 精算画面を、`設計書_画面構成.md` の3-4のとおり、段階を追って表示する形にしてください(売上、コストの内訳、今日の損益と所持金の変化、成長と評判の変化、次へ)。クリックまたは1.0秒のタイマーで次の段階へ進み、スキップとまとめて表示も用意してください。数字は、既存の精算(DayLedger など)の値をそのまま使い、計算を複製しないでください。破産のときは最後のページから、ゲームオーバー画面(到達日数、通算売上、最高日の売上、配達員の一覧、もう一度、タイトルへ)に進めてください。

## S-5: タイトル・遊び方・メニュー

**仕様**: 3-1、3-6のとおり。
- タイトル: `続きから`(セーブがあるときのみ)/ `最初から` / `遊び方` / `終了`。起動時はここから始まる
- 遊び方: 数ページの重ね表示(文字のみで構わない。内容は、1日の流れ、目安時間と注文の関係、ルートの選び方、お金と評判、の4ページ程度)
- メニュー(Esc): `再開` / `遊び方` / `タイトルへ`。営業中のタイトルへは確認を出す(進行が失われる)。**営業中はゲーム時間を止める**(メニューを開いている間)

**完了条件**: 起動 → タイトル → 続きから/最初から → 店 の流れが動く。Escでメニューが出て、営業中は時間が止まる。全検証が通る。

**指示文**
> タイトル画面、遊び方、メニューを追加してください。起動時はタイトルから始め、`続きから`(セーブがあるときのみ)・`最初から`・`遊び方`・`終了` を置いてください(M6-5のセーブ選択をここへ移してください)。遊び方は、1日の流れ、目安時間と注文の関係、ルートの選び方、お金と評判の4ページ程度の重ね表示にしてください(文字だけで構いません)。Escでメニュー(再開・遊び方・タイトルへ)を重ねて出し、営業中はメニューを開いている間ゲーム時間を止めてください。営業中にタイトルへ戻るときは、進行が失われることを確認するダイアログを出してください。

## 6. リスク
| リスク | 対処 |
|---|---|
| 画面を分けた結果、既存の検証が壊れる | CanvasGroupで非表示にする。S-0で依存を洗い出す。段階ごとに全検証 |
| 画面が多くなり、操作の手数が増える | 営業画面では、計画パネルを選択だけで開く(手数を増やさない)。店の画面は、1画面内のタブで済ませる |
| 精算の段階表示が、毎日だと煩わしい | `スキップ` と `まとめて表示`。設定で標準を切り替えられるようにする |
| 営業中の画面が情報不足で、判断しにくくなる | 地図の周りの帯に必要な情報(期限・体力・売上)を残す。遊んで調整する |
| 見た目の底上げ(V)と作業が重なる | この計画(S)を先に終え、Vは `UITheme` を新しい画面に適用する。Vの計画書は、この画面構成を前提に読む |
