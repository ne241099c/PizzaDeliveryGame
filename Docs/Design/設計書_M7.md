# 設計書・計画書: M7 調理工程と設備

M6までで、「注文が来る → すぐ出発できる」流れになっている。ピザ屋なのに、ピザを作る工程がない。
M7では、**調理工程**(注文を焼いてから配達に出る)と、**設備**(お金を使って店を強くする)を入れる。

実施の順番: 画面構成(S-0〜S-5) → **M7(C-1〜C-5)** → 見た目の底上げ(V) → 仕上げ(ビルド・README)。
(調理の状態は営業画面と店の画面に出る。画面ができてから作り、見た目の整備を最後にまとめて一度で済ませる)

## 1. 狙い

| 狙い | どうやって |
|---|---|
| 「ピザ屋」らしくする | 注文が、調理 → 焼き上がり → 配達の順に進む |
| 判断を増やす | 窯の台数が限られる。注文が重なると待たされ、目安時間の下限も変わる |
| お金の使い道をつくる | M6までは、お金が貯まる一方だった。設備への投資で、稼ぎを伸ばす/守る |
| 操作の負荷を上げすぎない | 調理は自動で進む。焼き加減の操作は**任意**(やれば得、やらなくても罰はない) |

## 2. 調理工程

### 注文の状態
```
発生 → 調理待ち → 調理中(窯) → 焼き上がり → 出発(配達中) → 到着
```
- 注文が発生すると、**自動で調理待ちの列(先着順)に入る**。空いている窯があれば、調理が始まる
- **出発できるのは、焼き上がった注文だけ**。調理待ち・調理中の注文は、選べない(カードに状態を表示)
- 期限は、これまでどおり**発生した時刻 + お届け目安時間**。調理に使った時間も、期限から引かれる
- 焼き上がったピザは、そのまま保温されている(冷めない。簡単のため)
- 調理待ち・調理中の注文も、期限が来ればキャンセルになる(従来どおり)
- 材料費(1件20)は、従来どおり**出発時**に払う(変更しない)

### 窯と調理時間
| 項目 | 初期値 | 調整項目 |
|---|---|---|
| 窯の台数 | 1 | 設備で最大3まで増やす |
| 調理時間(現実の秒) | 12 | `cookSeconds` |
| 1つの窯が同時に焼く数 | 1 | 固定 |

- 注文の発生間隔は、おおよそ 18秒(60秒設定・評判50)〜11秒(30秒設定)。窯1台・12秒では、30秒設定だと列ができ始める。ここで窯の増設に意味が出る

### 目安時間の下限(変更)
- 従来: 最遠の配達先を最良の配達員(運転1・土地勘1)が往復する時間 ×TimeScale ×1.1
- **新: 上記 + 調理時間(cookSeconds)**。調理に時間がかかる分、短くできる下限が上がる

### 焼き加減(任意の操作)
- 調理中のカードに、焼き具合のゲージ(0〜100%)が出る。ゲージは `cookSeconds` で100%になる
- 85〜95%の**ちょうどよい帯**に色がつく。この間に `取り出す` を押す(またはキー)と、**完璧**になる
- 何もしなければ、100%で自動的に取り出され、**標準**になる(罰はない)
- 95〜100%で押しても、標準(焦げない)
- 完璧にすると、その注文の得点に **+15** を加える(`perfectBakeBonus`。期限内に届けた場合のみ有効にするかは、遊んで決める)
- 操作は任意なので、**注意を払う余裕があるときだけ得をする**。配達の判断で忙しいときは無視できる
- 窯が複数でも、操作するのは「いま帯に入っているもの」だけ(複数が同時に帯に入っても、順に押せる)

### 自動プレイでの扱い
- 自動プレイは、焼き加減の操作をしない(すべて標準)。完璧の効果は、人が遊んで確かめる

## 3. 設備(お金の使い道)

店の画面に **「設備」タブ**を追加する(スタッフ・求人・経営・設備)。

| 設備 | 段階と費用 | 効果 | 維持費 |
|---|---|---|---|
| **オーブン増設** | 窯 1→2: 600 / 2→3: 1,000 | 窯の台数が増え、同時に焼ける数が増える | 固定費 +30/日(1台につき) |
| **広告** | 当日のみ。小100 / 中200 / 大350 | 当日の注文の発生が増える(需要 ×1.10 / ×1.20 / ×1.30) | なし(買った日のみ) |
| **バイクの強化** | 全員共通。Lv1→2: 500 / Lv2→3: 900 | 移動速度 ×1.08 / ×1.16。事故率 ×0.9 / ×0.8 | 維持費 +20/日(1レベルにつき) |
| **店舗の拡張** | 名簿の上限 4→5: 800 / 5→6: 1,400 | 雇える人数が増える | 固定費 +40/日(1段階につき) |

- 購入は**開店準備のときだけ**。所持金が足りなければ買えない(理由を表示)。買った設備は、翌日以降も続く(広告を除く)
- 値段・効果は、すべて調整項目
- **事故の修理費**: 事故が1回起きるたびに **30** を精算で引く(`accidentRepairCost`。0にすれば無効)
- 設備は、売る・戻すことはできない(簡単のため)

### 設備の位置づけ(判断のポイント)
- 窯を増やす: 30秒のような短い目安に挑むとき、調理がボトルネックになる
- バイクを強化する: 配達が間に合わないとき、事故が多いとき
- 広告: 配達員と窯に余裕があるときに、稼ぎを伸ばす
- 店舗を拡張する: 人数を増やして処理を増やす(日給と固定費が増える)
- 全部買うと維持費で苦しくなるので、**何に投資するかが経営の判断**になる

## C-1: 調理工程

**仕様**: 2章の「注文の状態」「窯と調理時間」「目安時間の下限」。
- 注文に状態(調理待ち / 調理中 / 焼き上がり)を追加。発生で調理待ちの列に入る(先着順)
- 窯の台数だけ同時に調理する。`cookSeconds` 経過で焼き上がり
- 出発(選択)できるのは焼き上がりのみ。注文カードに状態を表示(調理待ち・調理中(残り秒数)・焼き上がり)
- 目安時間の下限に `cookSeconds` を加える
- 期限切れは、状態にかかわらずキャンセル(従来の処理)
- 閉店時は、調理待ち・調理中の注文もキャンセル(従来の「未出発キャンセル」と同じ扱い)

**完了条件**
- 発生した注文が調理を経て、焼き上がってから出発できる。調理中のものは選べない
- 窯が1台で注文が重なると、列ができる(列の順は先着順)
- 期限が来た調理中の注文はキャンセルされ、窯が空く
- 目安時間の下限が `cookSeconds` 分だけ上がる
- 自動プレイが動く(焼き上がった注文だけを出発させる)
- 検証を追加する(状態遷移、列、期限切れ、下限)

**指示文**
> 注文に調理の状態(調理待ち・調理中・焼き上がり)を追加してください。注文が発生したら、自動で調理待ちの列(先着順)に入り、窯が空いていれば調理が始まります。窯の台数(初期1)だけ同時に調理でき、`cookSeconds`(初期12、現実の秒)で焼き上がります。出発できる(選べる)のは焼き上がった注文だけにし、注文のカードに状態(調理待ち、調理中(残り秒数)、焼き上がり)を表示してください。期限は従来どおり発生時刻+お届け目安時間で、状態にかかわらず期限が来たらキャンセルし、調理中なら窯を空けてください。閉店時は調理待ち・調理中の注文もキャンセルしてください。お届け目安時間の下限に `cookSeconds` を加えてください。材料費は従来どおり出発時に払います。自動プレイは、焼き上がった注文だけを出発させるようにしてください。検証を追加してください。

## C-2: 焼き加減

**仕様**: 2章の「焼き加減」。
- 調理中のカードに焼き具合のゲージ。85〜95%の帯に色。`取り出す`(ボタンとキー)で、帯の間なら完璧、それ以外は100%まで待って標準(95%以降に押しても標準)
- 100%で自動的に取り出す(標準)
- 完璧なら、得点に `perfectBakeBonus`(初期15)を加える。**期限内の配達のみ有効**(遅れた場合は無効)
- 品質(標準 / 完璧)を注文に保存し、到着時の採点で使う。精算に「完璧ボーナス」の内訳を表示
- 帯の位置・幅、ボーナスの額は調整項目

**完了条件**
- 帯の間に押すと完璧、押さなければ標準になる(罰なし)
- 完璧の注文を期限内に届けると、得点が+15される。遅れた場合は+0
- 精算に内訳が出る
- 検証を追加する(帯の判定、自動取り出し、ボーナス)。時刻を操作して再現する

**指示文**
> 調理中の注文のカードに、焼き具合のゲージ(0〜100%)を表示してください。85〜95%の帯に色をつけ、`取り出す`(ボタンとキー)を帯の間に押すと完璧、それ以外は標準になります。何も押さなければ100%で自動的に取り出されて標準になり、罰はありません。完璧の注文を期限内に届けたときだけ、得点に `perfectBakeBonus`(初期15)を加えてください。帯の位置と幅、ボーナスの額は調整可能にしてください。精算画面に完璧ボーナスの内訳を表示してください。時刻を操作して再現する検証を追加してください。

## C-3: 設備の基盤

**仕様**: 3章。
- `FacilityManager` を作る。設備(オーブン増設・広告・バイクの強化・店舗の拡張)の現在の段階、費用、効果の値を管理する
- 店の画面に「設備」タブを追加。各設備のカード(名前、現在の段階、次の段階の費用と効果、維持費、`購入` ボタン)
- 購入は開店準備のときだけ。所持金不足は理由を表示。購入で所持金が減り、準備費用として精算に別記する(採用費と同じ扱い)
- 維持費(オーブン・バイク・店舗)を、毎日の精算の固定費の内訳に加える
- 設備の段階を、セーブ・ロードに含める(広告は当日のみなので保存しない)
- 破産・最初からで、設備を初期状態に戻す

**完了条件**: 設備タブで買え、所持金と維持費が精算に反映される。セーブ・ロードで設備が残る。最初からで初期状態に戻る。検証を追加する。

**指示文**
> `FacilityManager` を作り、設備(オーブン増設、広告、バイクの強化、店舗の拡張)の段階・費用・効果の値を管理してください。段階と費用は `Docs/Design/設計書_M7.md` の3章の表のとおり、数値はInspectorで調整可能にしてください。店の画面に「設備」タブを追加し、各設備のカード(名前、現在の段階、次の段階の費用と効果、維持費、購入ボタン)を表示してください。購入は開店準備のときだけで、所持金不足なら理由を表示してください。購入費は準備費用として精算に別記してください(採用費と同じ扱い)。オーブン・バイク・店舗の維持費を毎日の精算に加え、内訳に表示してください。設備の段階をセーブ・ロードに含め(広告は当日のみなので保存しない)、破産と最初からで初期状態に戻してください。検証を追加してください。この段階では、設備の効果は反映しなくて構いません(C-4で行います)。

## C-4: 設備の効果

**仕様**
- オーブン増設: 窯の台数に反映(C-1の窯の台数を参照)
- 広告: 当日の需要係数に `×1.10 / ×1.20 / ×1.30`。当日の終わりに効果が切れる
- バイクの強化: 移動速度 `×1.08 / ×1.16`、事故率 `×0.9 / ×0.8`。全員に適用。出発時に確定する(移動中に変わらない)
- 店舗の拡張: 名簿の上限(初期4)を5、6に増やす(`RecruitmentManager`が参照)
- 事故の修理費: 事故1回につき `accidentRepairCost`(初期30)を精算に加え、内訳に表示

**完了条件**: 各設備が、効果どおりに働く。目安時間の下限・日給・採用の計算が壊れない。検証を追加する。

**指示文**
> 設備の効果を反映してください。オーブン増設は窯の台数、広告は当日の需要係数(`×1.10 / ×1.20 / ×1.30`、当日の終わりに切れる)、バイクの強化は移動速度(`×1.08 / ×1.16`)と事故率(`×0.9 / ×0.8`)で、全員に適用し、出発時に確定してください。店舗の拡張は名簿の上限(初期4)を5、6に増やしてください。事故の修理費として、事故が1回起きるたびに `accidentRepairCost`(初期30)を精算に加え、内訳に表示してください。目安時間の下限と、日給・採用の計算が壊れないことを確認し、検証を追加してください。

## C-5: 自動プレイ対応と測定

**仕様**
- 自動プレイの方針に **設備購入** を追加: `しない` / `する`(開店準備で、所持金が `価格 + 予備金100` 以上なら、**窯 → バイク → 広告(小) → 店舗** の優先順に、1日1つまで買う。すでに最大のものは飛ばす)
- CSVに、設備の段階、調理待ちの最大の長さ、窯の稼働率、設備の維持費を追加する
- 次の比較を、同じシードで30日ずつ(破産したら終了)行う:

| 比較 | 出発 | 雇用 | 目安 | 訓練 | 設備 |
|---|---|---|---|---|---|
| F | まとめ | する | 調整 | しない | しない |
| G | まとめ | する | 調整 | しない | する |
| H | まとめ | する | 30固定 | する | する |

**調整の目標**
- 窯1台のままでは、30秒設定で列ができて遅れが増える(Hで確かめる)
- 設備ありのGが、なしのFより、20日目の所持金か利益が高い(設備が投資として成り立つ)
- 全設備を最大にすると、維持費が重く、利益が伸びすぎない(設備を買い揃えて終わりにならない)

**指示文**
> 自動プレイの方針に、設備購入を追加してください。`する` は、開店準備で所持金が `価格 + 予備金100` 以上なら、窯 → バイク → 広告(小) → 店舗の優先順に、1日1つまで買います(最大のものは飛ばす)。CSVに、設備の段階、調理待ちの最大の長さ、窯の稼働率、設備の維持費を追加してください。次の3通りを、同じシードで30日ずつ(破産したら終了)実行し、CSVと要約を報告してください。F: まとめ・雇用あり・目安調整・訓練なし・設備なし。G: Fと同じで設備あり。H: まとめ・雇用あり・目安30固定・訓練あり・設備あり。計画書の目標(窯1台で30秒だと列ができる、設備が投資として成り立つ、全設備を最大にしても利益が伸びすぎない)に照らして、結果を報告してください。数値は変えず、報告後に私の判断を待ってください。

## 6. リスク
| リスク | 対処 |
|---|---|
| 調理が加わり、営業中の操作が忙しくなる | 調理は自動。焼き加減の操作は任意で、無視しても罰なし |
| 調理のぶん、期限が厳しくなり、これまでの調整が崩れる | 目安時間の下限を調理時間ぶん上げる。`cookSeconds` を調整項目に |
| 設備が強すぎる/弱すぎる | 費用・効果・維持費をすべて調整項目に。C-5で測る |
| 設備の維持費で、日をまたぐ収支が崩れる | 精算の内訳に表示。維持費の合計の上限を見る(C-5) |
| 画面構成(S)の途中で作業が重なる | 順番を守る(S → M7 → V)。M7はSが終わってから |
