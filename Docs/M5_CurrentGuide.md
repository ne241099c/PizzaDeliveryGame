## 遊び方

1. `Assets/Scenes/SampleScene.unity` を開いてPlay。1日目の開店準備になる。初期資金300、評判50、名簿はAoiとRen。
2. 準備画面で6能力・日給・求人を見る。`Hire` は日給3日分、`Fire` は日給1日分を支払う。最初は採用資金が足りない候補が多いので、まず営業して貯める。拒否理由は画面下に出る。上限4人、最後の1人は解雇できない。
3. 上部の `Delivery promise` で目安時間を選び、`Start business` を押す。準備中は時間が進まない。短い目安ほど注文が増えるが、期限も短くなる。発生済み注文の期限は変わらない。
4. 注文を1〜2件とIdleの配達員を選ぶ。地図の道、または右の道路候補を順に選び、目的地を通って店舗へ戻る。行きと帰りは違う道でもよい。`Individual reference` と自作ルートの時間差で比較する。
5. `Dispatch` で出発する。`Dispatch with suggestion` なら推奨経路でそのまま出発する。積載量を超える出発は拒否される。出発時に注文1件20の材料費が引かれる。
6. 到着時に遅延減点・接客チップを反映した得点が売上として所持金に入る。事故の停止15秒は到着予定を遅らせるが、停止中の燃料費は増えない。体力が減ると次の出発が遅くなり、店舗で待つと回復する。
7. 営業時間300秒で閉店。未出発注文をキャンセルし、全員の帰還後に精算する。閉店キャンセルの評判低下は初期0、期限切れキャンセルは従来どおり5。営業中の所持金マイナスは許す。
8. 精算画面に売上・材料費・燃料費・全員の日給・固定費・損益・所持金の変化が出る。**画面内をスクロール**すると配達員の積載量と残り体力まで見られる。
9. `Next day` で翌日の準備へ。所持金・評判・名簿・通算記録を持ち越し、体力・注文・時計・その日の集計をリセットする。求人も入れ替わる。
10. 精算後の所持金が0未満なら破産。到達日数・通算売上・最高日売上を表示し、`Start over` で初期状態へ戻る。下部の `Reset` もキャンペーンを最初からにする。

採用費・解雇手当は「準備費用」として営業の損益とは分けて精算画面に表示する。所持金は `準備前の所持金 + 営業損益 − 準備費用` と一致する。

## Inspectorで変えられるもの

Play停止中に `GameManager` を選んで変更すると保存される。Play中の変更は試行用。

| Component | 項目 |
|---|---|
| BusinessEconomy | 開始資金300、材料20/件、燃料0.4/距離、日給の基礎50・能力係数40・積載係数30、固定費150 |
| CampaignManager | 破産猶予0日。連続したマイナス精算の日数で判定し、所持金が回復した精算で連続日数を0にする |
| RecruitmentManager | 上限4人、候補2〜3人、採用3日分・解雇1日分、能力の基準値と補正幅、得意/不得意の数、積載量の確率、名前一覧、固定シード |
| ReputationManager | 初期評判50、通常キャンセル5、閉店キャンセル0、需要への係数 |
| DeliveryDynamics / OrderSpawner | 既存の体力・事故・注文頻度等に加え、固定シードとその値 |
| DaySimulationSettings | 比較日数10、目安30/60/120秒、シード20261022、時計刻み0.25秒、1日の時間上限 |

名簿・6能力は `DeliveryPersonSelector`、移動係数は `MapRoot` の `MapManager` にある。`ManualDeliveryRoute` と `RoadPathfinder` はM5では変更していない。

## 自動プレイ

1. Play中に `Tools > Pizza Delivery > Simulate Days` を開く。
2. 日数・目安時間の配列・シードを指定し、`Run comparison` を押す。各目安時間は初期状態から始まる。**現在の営業状態はリセットされる**。
3. 期限が近い注文を1件ずつ、待機中の配達員へ実際の推奨出発処理で出す。雇用・解雇は行わず、破産したらその設定は終了。
4. 日別の結果がConsoleと `Docs/M5_Simulations/comparison-日時.csv` に出る。`Show CSV` でファイルを表示できる。CSVの `promise_seconds` は物理下限で補正後の実際の目安時間。

既存の `GameClock.Advance`、注文生成、`DeliveryPlannerUI.DispatchWithSuggestion`、事故、到着採点、精算を利用する。シミュレーター内で売上・費用・評判の式を再実装していない。注文・事故・求人は独立した乱数列を使い、同一シードを再現可能にした。

## 検証

新しくPlayを開始して実行する。既定の仕様数値を検証するため、Inspectorで数値を調整した後は既定値の期待値と異なることがある。

- `Tools > Pizza Delivery > Validate M5 (Play Mode)`：既存169項目 + M5の67項目。時刻と注文を操作して精算・雇用・破産まで進め、最後に初期状態に戻す。時計の自動進行は止めたままなので、通常の遊びに戻るときはPlayを入れ直す。
- `Tools > Pizza Delivery > Validate Reset (Play Mode)`：初期化8項目。
- `Tools > Pizza Delivery > Validate M5 Simulation (Play Mode)`：既定3設定を各10日上限で2回走らせ、CSV全フィールドの一致と日別の収支など93項目を確認する。結果は `seed-20261022.csv`。
- 旧M3検証は開店準備中でも実行可能。旧M4 Play Flowメニューは現在のM5営業フロー検証へ接続済み。

最終合計 **337項目PASS**。自動プレイ2回で合計52日分を処理し、実行時エラーなし。これは操作の自動再現と測定で、人が数日遊んだ面白さの評価とは区別する。
