# 設計書・計画書: 目標と報酬(お金が溜まる「意味」を作る)

> 作成: 2026-10-24。きっかけ: 「お金が溜まってきても目的がなくておもんない」(ユーザー)。
> ユーザーの判断: 長期=ローン返済、中期=店ランクの昇格、短期=日替わりミッション、を採用。**通常モード(n日間)とエンドレスモード**を用意し、**お金以外の報酬**も入れる。

## 1. 狙い

| 層 | 狙い | 中身 |
|---|---|---|
| 長期 | ゲームに「終わり」と「評価」がある | 通常モード: n日間の経営成績でランク(エンディング)。エンドレス: 記録を伸ばす |
| 中期 | 「次はこれが開く」が見える | **店のグレード**の昇格。昇格で、新しい街区・ピザ・設備・求人が開く |
| 短期 | 毎日の動機 | 日替わりミッション(任意、報酬つき) |
| 資金の意味 | お金が「手段」になる | **ローン(借金)**の返済と、投資(設備・内装)のどちらに使うか、を選ぶ |
| お金以外 | 続ける理由と収集の楽しみ | 称号(実績)、図鑑、店のカスタマイズ、記録 |

## 2. ゲームのモード

**基本の仕組みは共通**。違いは「n日目に結果画面で何を選ばせるか」だけ。

### 2-1. 通常モード(n日間)
- **20日間**(確定。データで変更可能)で**ローンを完済する**のが目標。経営を続ける
- **20日目の精算のあと**に、**結果画面**(エンディング): **ローンを完済できたか**を判定(完済=クリア / 未完済=「返済できなかった」エンディング。どちらも続行・終了を選べる)→ 最終成績を表示 → **ランク**を決定 → 「**続ける(エンドレスへ)**」か「**終了(タイトルへ)**」を選ぶ
- **所持金がマイナスになったらゲームオーバー**(結果画面は出す。ランクは付かない/「破産」)
- **スコア**(初期案。調整項目): `最終の純資産(所持金 − ローン残高)` + `累計売上 × a` + `評判 × b` + `★3率 × c` + `期限内率 × d`。式の係数と、ランク(S/A/B/C/D)の閾値は、測定(R-7)で決める
- ランクの意味づけ: S=街のレジェンド / A=名店 / B=人気店 / C=普通の店 / D=なんとか続いた

### 2-2. エンドレスモード
- n日目の結果画面で「**続ける**」を選ぶと、**そのまま経営が続く**(エンディングなし、日数制限なし)。タイトルから、最初から「エンドレス」を選んで始めることもできる
- **所持金がマイナスになったらゲームオーバー**
- **記録**: 最高生存日数、最高所持金、最高の純資産、最高の評判、最高の店グレード
- **自由な目標**: プレイヤーが**目標カード**を設定できる(テンプレートから選ぶ。例: 「◯日までに純資産◯円」「評判◯」「◯日連続で遅れ0件」)。達成で称号。HUDに小さく表示

### 2-3. 共通化の方針
- 経営の中身(営業・精算・成長・設備・マップ)は、**モードによらず同じ**
- モードの違いは、`GameMode`(Normal / Endless)として持つ: ①結果画面を出す日(n日) ②結果画面の選択肢 ③ゲームオーバーの扱い、の3点だけ
- セーブには、モードと、通常モードで「結果画面を見たか」を保存

## 3. ローン(借金)

> **確定(2026-10-24)**: **20日で完済できる**ように作る。ローン初期額 L は、R-0/R-7 で測る「標準的な遊び方の20日間の純利益の合計」の**約8割〜9割**を目安に決める(上手く遊べば余裕、普通なら一杯一杯)。利息は日1%だと重いので、初期値は **0.5%/日**(調整)。**救済(緊急の借り増し)は入れない**。

- 開始時に**ローン残高**(初期値 `L` 円。調整項目)がある。**店を始めるために借りたお金**という設定
- **毎日の精算**で、**利息**(`残高 × r`。初期値 r=1%/日。調整項目)が加わる。返済は**プレイヤーが任意**(精算画面で、余ったお金から返済額を選ぶ。最低返済額なし)。→ **「返す」か「投資する」か**の判断が生まれる
- 完済すると、**「完済」の称号**と少額のボーナス。通常モードのスコアは**純資産(所持金 − 残高)**で評価されるので、返済も投資も、最終的に損得で比べられる
- **ゲームオーバー**は、**所持金がマイナス**になったとき(ローン残高ではない)。残高は、所持金とは別に表示
- 精算画面の予測: 「あしたの固定費で、所持金が足りなくなりそうです」の**警告**(破産前に気づける)
- 救済(任意・あとで決める): 緊急の借り増し(利息高め)。最初は入れない

## 4. 店のグレード(中期の目標)

| グレード | 名前 | 昇格の条件(初期案。調整項目) | 開くもの(例) |
|---|---|---|---|
| 1 | 屋台 | (開始) | 最初の街区、基本のピザ |
| 2 | 街の人気店 | 評判 ≥ 40、累計売上 ≥ A1、期限内率 ≥ 80%(直近の5日) | 新しい街区、新しいピザ、作業台2台目 |
| 3 | 行列のできる店 | 評判 ≥ 70、累計売上 ≥ A2、★3率 ≥ 30% | さらに街区、新しいピザ、設備(窯・バイク)、日替わりの変化 |
| 4 | 名店 | 評判 ≥ 90、純資産 ≥ A3 | 最後の街区、全ピザ、特別な求人 |

- 昇格は**自動で判定**(精算のとき)。**演出**(「街の人気店に昇格!」、開いたものの一覧)を出す
- **マップの拡張**(`設計書_マップ生成.md` のG-3)と**ピザの種類の解禁**(S2-6)は、**日数ではなく、昇格のごほうび**として開く(日数は保険の上限)
- 昇格の条件の数値は、測定(R-7)で決める(20日で、標準の遊び方なら、グレード3〜4に届く程度)

## 5. 日替わりミッション(短期)

- 毎朝(店の画面)に、**ミッションが3つ**提示される。**任意**で、**1つ以上**を「今日の目標」に選べる(選ばなくてもよい)
- 達成の判定は、**精算のとき**。達成で、**少額のお金**(初期値 30〜100円)と、実績ポイント
- ミッションの種類(テンプレート。難しさは店のグレードに応じて):
  - 品質: 「★3を◯枚」「失敗0枚」
  - 配達: 「遅れ0件」「1便で3件まとめる」「裏道を◯回使う」「自動ルートより◯秒速く」
  - 経営: 「売上 ◯円」「廃棄0枚」「内勤に◯枚任せる」
- 同じミッションが続かないように、日ごとに**シードで選ぶ**(再現できる)

## 6. お金以外の報酬

> **確定**: 店のカスタマイズ・特別な求人・ハードモードは**入れない**(R-5は削除)。報酬は称号・図鑑・記録に絞る。

| 種類 | 中身 | 重さ |
|---|---|---|
| **称号(実績)** | 条件を満たすと得る。例: 「遅れゼロの日」「まとめ名人(1便で3件)」「裏道の達人」「完済」「焦げなし10日」。タイトルの「記録」画面で一覧 | 必須 |
| **図鑑** | ピザの図鑑(作ったピザ、★3を出した種類)、街の図鑑(訪れた街区、見つけた近道)。埋める楽しみ | 必須 |
| **記録** | ハイスコア、最高生存日数、最高所持金、最高グレード。通常モードのランクの履歴 | 必須 |

- **永続データ**(称号・図鑑・記録・解放済みの見た目)は、**1回のプレイのセーブとは別**に保存する(`ProfileData`)。新しいゲームを始めても消えない
- 称号のデータは、**条件の定義(データ)**として持つ(コードに直書きしない)

## 7. 画面への影響

| 画面 | 変更 |
|---|---|
| タイトル | `最初から` で、**通常 / エンドレス**を選ぶ。**記録**(称号・図鑑・ハイスコア)のボタン。設計書の4-1にも反映 |
| HUD(店内) | 小さく、**ローン残高**、**今日のミッション**、(エンドレスは自由な目標) |
| 店の画面(朝) | **今日のミッション**を選ぶ。**グレード**と、次の昇格までの進み具合 |
| 精算 | **ローンの返済**(スライダーか金額ボタン)、ミッションの達成、昇格の演出、新しい称号 |
| 結果画面(n日目) | 最終成績、ランク、称号、「続ける / 終了」。通常モードのエンディング |
| 記録画面 | 称号一覧、図鑑、ハイスコア、最高記録 |
| ゲームオーバー | 破産の結果、記録、「もう一度 / タイトルへ」 |

## 8. 既存への影響

| 対象 | 変更 |
|---|---|
| 精算 | 利息・返済・ミッション・昇格を追加。既存の式(売上・コスト・損益)は**変えない** |
| 所持金 | ゲームオーバー(マイナス)の扱い。ローン残高は別の値 |
| マップ拡張・ピザの解禁 | 日数から**昇格**へ(`設計書_マップ生成.md` 4-1、S2-6を更新) |
| セーブ | モード、ローン残高、グレード、ミッション、結果画面の状態を追加。永続データは別ファイル |
| 自動プレイ | 方針に「返済の割合」「ミッションの選び方」を追加。結果(スコア・ランク・グレード)を記録 |
| 検証(3,772項目+新規) | 既存は通り続ける。新しい検証を追加 |

### どのタスクにも共通の依頼
> 既存の実装を調べ、再利用できるものを使ってください。仕様は `Docs/設計書_目標と報酬.md` に従ってください。得点・評判・精算の既存の式、`ManualDeliveryRoute`、`RoadPathfinder` は変更しないでください(追加する式は別に持つ)。数値(日数・ローン・利息・閾値・報酬額)は、Inspectorで変えられる `[SerializeField]` かデータにしてください。各段階の終わりに、既存の全検証と新しい検証が通ることを確認し、その段階だけをローカルでコミットしてください(メッセージの先頭は `R-1:` のように段階の番号。pushはしない。`git add .` は使わない。Packages変更、`.DS_Store`、`.codex`、`Assets/_Recovery` は含めない)。通らなければ、そこで止まって原因を報告してください。Unity操作は一度に一人なので、`Docs/Handoff/Workboard.md` に担当を書いてください。

## R-2: ローンと店のグレード

**仕様**: 3章・4章。ローン残高(初期値L)、毎日の利息(残高×r)、精算画面での任意の返済、純資産(所持金−残高)の表示、完済、警告(あした足りなくなりそう)。店のグレード(屋台/街の人気店/行列のできる店/名店)、昇格条件の判定(精算のとき)、昇格の演出、**解放の仕組み**(昇格で、街区・ピザの種類・設備・求人プールが開く。まず仕組みと仮の解放のみ。実際の中身はG・S2-6と連携)。

**指示文**
> ローンと店のグレードを実装してください(`Docs/設計書_目標と報酬.md` のR-2)。開始時にローン残高(初期値L円。調整可能)を持ち、毎日の精算で利息(残高×r。初期値1%)を加え、精算画面で、余ったお金から任意の額を返済できるようにしてください(最低返済額なし)。純資産(所持金 − 残高)を表示し、完済時に称号の仕組みに知らせてください(称号は後のR-4)。ゲームオーバーは所持金のマイナスのままにし、精算画面に、あしたの固定費で足りなくなりそうなときの警告を出してください。店のグレード(屋台、街の人気店、行列のできる店、名店)を作り、昇格の条件(評判、累計売上、直近の期限内率、★3率、純資産。数値はデータ)を精算のときに判定して、昇格の演出(仮の見た目でよい)を出してください。昇格で、街区・ピザの種類・設備・求人の解放が起きる仕組みを、データ駆動で作ってください(中身は、マップ生成とピザの種類の実装で追加します。いまは仮の解放項目でよい)。ローン残高とグレードをセーブに含めてください。既存の精算の式(売上・コスト・損益)は変更せず、追加の処理として加えてください。既存の全検証と、新しい検証(利息、返済、完済、警告、昇格の判定、解放の仕組み、セーブ)が通ることを確認してください。

## R-3: 日替わりミッション

**仕様**: 5章。毎朝3つのミッションを提示(シードで再現)、任意で選ぶ、精算で判定、達成で報酬(お金・実績ポイント)。テンプレート(品質・配達・経営)と、グレードに応じた難しさ。

**指示文**
> 日替わりミッションを実装してください(`Docs/設計書_目標と報酬.md` のR-3)。毎朝、店の画面に、ミッションを3つ提示し(シードで再現できる。同じものが続かないように)、プレイヤーが任意で1つ以上を「今日の目標」に選べるようにしてください(選ばなくてもよい)。ミッションはテンプレートのデータで定義し(品質: ★3を◯枚・失敗0枚、配達: 遅れ0件・1便で3件まとめる・裏道を◯回・自動ルートより◯秒速く、経営: 売上◯円・廃棄0枚・内勤に◯枚)、店のグレードに応じて難しさが変わるようにしてください。達成の判定は精算のときに行い、達成で、お金(初期値30〜100円)と実績ポイントを加えてください。精算画面に、達成の結果を出してください(仮の見た目でよい)。必要な統計が足りない場合は、R-0の報告で挙げたものを追加してください。既存の全検証と、新しい検証(ミッションの生成の再現性、選択、達成の判定、報酬、セーブ)が通ることを確認してください。

## R-4: 永続データ(称号・図鑑・記録)

**仕様**: 6章。`ProfileData`(1回のプレイとは別のファイル)。称号(条件はデータ)、図鑑(ピザ・街区)、記録(ハイスコア・最高生存日数・最高所持金・最高グレード・ランクの履歴)、タイトルの「記録」画面(仮の見た目)。

**指示文**
> 永続データと記録画面を実装してください(`Docs/設計書_目標と報酬.md` のR-4)。1回のプレイのセーブとは別のファイル(`ProfileData`)に、称号、図鑑(作ったピザの種類と★3の有無、訪れた街区)、記録(ハイスコア、最高生存日数、最高所持金、最高グレード、ランクの履歴)を保存してください。新しいゲームを始めても消えないようにしてください。称号は、条件のデータ(統計の名前、比較、しきい値)で定義し、条件を満たしたときに得て、通知を出してください(例: 遅れゼロの日、まとめ名人、裏道の達人、完済、焦げなし10日)。タイトルに「記録」ボタンを追加し、称号一覧・図鑑・記録を見られる画面を作ってください(承認モックは後で渡します。仮の見た目でよい)。ファイルの破損・バージョン違いでゲームが落ちないようにしてください。既存の全検証と、新しい検証(称号の条件判定、図鑑、記録の更新、永続とプレイセーブの分離、破損時の復旧)が通ることを確認してください。

## R-6: 画面とR-7: 測定
- R-6: モック(PM)→ 実装。対象: タイトルのモード選択と記録、HUD、店(ミッション・グレード)、精算(返済・ミッション・昇格)、結果画面、記録画面。**まず私がモックを作り、承認されたものをCodexに渡す**
- R-7: 自動プレイで、20日の通常モード(ローン完済の可否も記録)(スコア・ランク・昇格のタイミング・返済の戦略(早く返す / 投資を優先))を同じシードで測定。**数値は変更せず、報告して判断を待つ**

## 10. リスク

| リスク | 対処 |
|---|---|
| 目標を足しても、やはり面白くない | 先にR-1・R-2だけを作り、遊んで判断。条件・ローン・利息は調整項目 |
| ローンの利息で、序盤が苦しすぎる | 返済は任意で、最低返済額なし。ゲームオーバーは所持金のマイナスのみ。R-7で測る |
| 昇格の条件が厳しい/ゆるい | データにして、R-7の測定と、あなたの感触で調整 |
| 作業量が大きい(店内シーン+商品+マップ+目標) | 順番を守る。最小の線(R-0〜R-2)を優先し、R-3・R-4は後回しにできる |
| 称号・図鑑の絵が多くて間に合わない | まず文字とアイコンだけ。店のカスタマイズ(絵が増える)は後回し |
| 永続データの破損 | バージョンを持たせ、破損時は初期化せずバックアップから復旧(R-4の検証) |

## 11. 未確定・遊んで決めること
- (確定)通常モードは20日でローン完済。グレードは4段階。救済なし。カスタマイズ・特別な求人・ハードモードは入れない
- ローンの初期額 L と利息 r(20日で完済できる水準に。R-7で測定)
- 昇格の条件の数値と、グレードの数(4つでよいか)
- スコアの式の係数とランクの閾値
- ミッションの報酬額と、選べる数
- エンドレスの自由な目標のテンプレートの種類
