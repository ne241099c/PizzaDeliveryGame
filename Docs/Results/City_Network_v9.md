# 道路網v9・渋滞・スローモーション廃止・内勤の訓練（2026-10-24）

担当：Claude Code。shop、ローカルのみ、pushなし。方針（ユーザー）：忙しさを売りにし、道の変更は渋滞を避けるときに使う程度とする。

## 依頼と対応

| 依頼 | 対応 |
|---|---|
| 家と家の間隔を縮める | v9：交差点の最低間隔 2.1→1.5、街の広がり 1.8→1.15。街の幅 約60→約35、家どうしの平均距離 約3.0→約1.9 |
| 配達指示のスローモーションをやめる | `GameClock.planningTimeRate` を1（シーンの値も0.1→1）。早送りボタン（押している間4倍）は残した |
| 渋滞を増やす | v9：毎日、大通りの約3割が渋滞（速さ0.3〜0.6倍、街のseedと日付で決まり日ごとに変わる）。1本ふさぐと街が分かれる道と、お店に直結する道は渋滞させない。自動ルートは渋滞を考えない |
| 一本道で着いてしまう→エッジを繋ぎまくる | v9：新しい交差点から最大3本を追加でつなぎ、行き止まりに残った交差点もつなぎ直す。生成の条件として「どの道を1本ふさいでも、家の9割以上へお店から行ける」（`minimumMultiRouteShare`）。満たさない街は作り直す |
| 内勤も訓練できるように | 厨房スタッフのカードの「訓練」で手際か丁寧さを選ぶ。費用は配達員の訓練と同じ式。その日の営業の前半は厨房に入らず、半分で能力+0.1。開店前なら全額返金で取り消し。セーブに残る（`kitchenTraining`、古いセーブは「なし」として読む） |

続きからの街（25日目）：v9・100軒・大通り186本のうち渋滞55本。保存済みの街（v8以前）は、続きからの開店準備でv9に作り直される。

## 構成

- `CityValidator.CutRoads`：ふさぐと街が分かれる道（グラフの橋）。2通りの行き方の判定と、渋滞の除外に使う。
- 渋滞は `MapManager.PrepareCity` で日ごとに設定（生成結果そのものは日によらない）。
- 内勤の訓練：`TrainingManager`（`KitchenTrainingAssignment`）、`KitchenStaff.InTraining`、`CookingManager` が訓練中のスタッフに仕事を回さない。ハブは既存の訓練ダイアログを2択で使い、説明文を相手に合わせる（HubView.prefabのNoteを参照に追加）。
- 検証：`KitchenTrainingValidation`（新規、Test Runner登録）、`CityGenerationValidation.RunNetwork` をv9の条件（v8より家が近い、2通りの行き方）に更新。

## 確認

- Test Runner 27件通過（1回目はShopの「少し遅れても配達成功」が、お店そばの道の渋滞で大きく遅れて失敗。お店に直結する道を渋滞の対象から外して通過）。
- Playで続きからの街・配達指示（スローなし：進行倍率1）・内勤の訓練の申し込みと見通しの訓練費・訓練ダイアログを撮影：`Docs/UI_Screens/city-network-v9/`。
- 通常セーブ・最高記録は検証の前後でハッシュ一致。
- 未確認：渋滞と小さな街での経営バランス、長時間シミュレーション。
