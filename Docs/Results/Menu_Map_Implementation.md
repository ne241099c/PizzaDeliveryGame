# ピザ・生成マップの実装記録

2026-10-23 / shop / Codex。ユーザー添付の設計書をDocsへ反映。既存実装の差分から進める。通常セーブの保存抑制を使用、pushなし。

## 配達速度と窯のキュー

配達速度を1.2倍（所要時間は従来の約83.3%）にした。MapManagerのdeliverySpeedMultiplierで調整。閉店後の8倍速は維持する。
窯は全台共通の先着順キュー。満杯でも完成したピザを受け付け、作業台を空ける。空き次第自動で焼き始める。内勤のピザも同じキュー。手動ピザの取り出しタイミングの操作は維持する。窯ごとの固定予約にはせず、最初に空いた窯を使う判断。

関連検証312項目通過（新規8、M7 83、店内51、M3/M4 170）。旧仕様の「満杯の窯は拒否」をキュー受付に更新。通常保存抑制のまま新規→タイトルで終了。

## S2-6：ピザ3種類

マルゲリータ100、ペパロニ120、シーフード150。設備のメニュー拡張は400/700、1段階ごと維持費10。具材の指定・2工程のシーフード・焼き+1秒・内勤と手動・種類別の得点/チップ・精算表示を接続。シーフードの追加具の作業は暫定2秒（Inspector）で、標準所要の下限にも反映。旧セーブはメニュー0として読める。いかのトレイとピザの具は既存SVG描画ツールを拡張して生成。

関連167項目通過（新規ピザ25、窯/速度8、M7 83、店内51）。自動プレイは既存の内勤処理を使用するため、種類別の工程を複製しない。

## G-0：調査と実装判断

現在のMapDefinitionはNodes/Edgesのみ。ロードはMapManager.Start、経路はRoadPathfinder、手作業の道順はManualDeliveryRoute。土地勘は配達員の能力であり、道ごとの学習履歴は現状ない。道IDを固定し、名簿・経験を再初期化せずに地図だけを更新する。注文は全配達先から等確率、地図の飾りは固定矩形と川だった。

基準地図は5節点・6道路・配達先2、総距離46（10+10+11+5+7+3）、行き止まり率20%（店）。往復到達2/2、一方通行0、橋0、近接配達先1ペア（距離3）。熟練者の最短経路は2件とも裏道有利（大通りとの差は距離重み換算5.6667、約15〜17%）。大通りの混雑区間はN1-N2には迂回があるが、Store-N1にはない。配達先は2件だけなので近・中・遠の3帯を満たせない。生成器の品質検査を、そのまま基準地図に要求することはできない。

ランタイム生成を選択する。シード・日数から再現でき、自動プレイと共通化できるため。生成物は一時ScriptableObjectであり、元のMapDefinition形式・資産は変更しない。テンプレートと生成閾値をMapManagerのInspectorへ集約し、描画用の街区・橋・需要はサイドデータに持たせる。G-0末尾の「報告して停止」は資料中の段階別指示文として扱い、今回の一括実装依頼に従い続行する。

## G-1：テンプレートと生成器

住宅街・商店街・公園・川沿い・団地をデータで定義。主道路・裏道・一方通行・2本の橋・配達先・需要/種類の重みを生成する。各街区の乱数を独立させ、後から増やしても既存の形とIDは維持する。Editor専用の Tools > Pizza Delivery > City Generator でシードと日数を指定して地図と指標を確認できる。

固定3シードで再現性・道ID/座標の維持・品質の12項目通過。この時点では生成器だけで、本番キャンペーンへの接続はG-3で行う。

## G-3：キャンペーン・日数・保存

新規ゲームからシード付きの街を使用。開始3街区、6日目5、11日目8、21日目12（MapManagerのcitySettingsで調整）。既存道路のID・位置・距離を維持し、追加だけを行う。11日目以降は3日単位で一部の大通りを徐行工事にし、変更後も検査して採用する。閉鎖はせず徐行とする判断。開店準備に街情報、精算に拡張予告を表示。

セーブにはシード・街区数・日数・形式バージョンを追加。工事は同じシードと日数から再現する。旧セーブ（cityなし）は元の地図を保つ。道ごとの学習データは既存実装にないため、配達員の土地勘能力・経験をそのまま保持する。

関連17項目通過：新規/別シード/再開、6・11・21日目への拡張、土地勘保持、同日工事の再現、旧セーブ互換。MapDefinition・ManualDeliveryRoute・RoadPathfinderは変更していない。

## G-4：街区別の注文と実プレイ測定

発生先は解放済みの家だけから、街区需要の重みで抽選。全体の頻度は街区需要の平均を既存の目安・評判・広告係数に掛ける（街区数に比例して無制限に注文を増やさない判断）。種類はメニュー解禁を必須とし、街区の好みで重み付けする。街区拡張だけでは商品を自動解禁しない。

関連283項目通過（街区注文5、ピザ25、M7 83、M3/M4 170）。地図切替前から保存抑制する固定サンプル検証用スコープを追加。生成地図の検証は別に行い、旧サンプルの計算期待値と混同しない。Unity JSONがnullのcityを空オブジェクト化する問題を発見し、generatedフラグで旧地図を明示。旧セーブJSONの追加確認を含め、キャンペーン18項目も通過。

G-2の残り：合格した100街（3/5/8/12街区を25街ずつ）で実際のGameClock・調理・配達・採点・精算を使う3日間、計300日を完走。これは地図の詰みを分離するため検証専用の初期資金10000で実行した。ゲーム本体や収支測定の初期資金は変更していない。結果は `Docs/Simulations/MapGeneration/Autoplay.csv`。通常セーブ・最高記録の前後一致も確認。

## G-5：描画と表示の仕上げ

生成街区に公園・木・団地/商店街の建物・川・橋・街区名・通り名を表示する。接続口、配達先候補、飾りの有無もテンプレートのInspectorデータ。ズームを引いたときは名前札・細部・つまみを省き、ピンを小さくする。注文名は一覧に残し、ルート線は直接ドラッグできる。道路・節点は空間ごとの描画グループで画面外を除外する。街区拡張時は追加の地面をフェード表示する。

表示のため同じ距離経路を毎フレーム再計算していたので、地図更新番号ごとに再利用する。注文や視点が変わらなければピンの再設定も省く。ManualDeliveryRoute/RoadPathfinderや時間の式を複製していない。通常地図と道数10倍以上の検証コピーで測定し、画像も目視確認した。これはEditor・1920x1080・時計停止中の地図/ルート表示を各90フレーム測った値であり、製品ビルドや営業中の負荷全体の保証ではない。各フレームのばらつきもCSVのp95に残す。

仕上げで修正した点：同じ固定シードで新規開始した場合も保存の街区数を再設定する。窯の同時刻受付は連番で先着順を保つ。シーフードの2種類の具は順不同で正解とし、1種類目から絵を表示する。次に必要な具も表示する。待ち伝票には「窯待ち何番」を出す。営業開始時に注文0件でも前の注文行を消し、指示盤の未選択道路を赤いルート線と混同させない。

実行した仕上げの関連確認：キャンペーン19、ピザ25、窯/速度11、表示/キャッシュ8、生成/テンプレート13項目が通過（段階内で変更のあった範囲だけ再確認。重複実行分を合算して全体件数とはしない）。加えて、窯待ちの表示・空の新日の注文行・画像を確認。テスト/撮影後に通常セーブと最高記録のバイト一致を確認し、保存抑制中に新規→タイトルへ片付けた。

## S2-7追補：内勤の方針・J/K/L比較

DaySimulationSettingsに内勤の初期人数（-1=通常の開始人数）・内勤の雇用の有無・内勤不在時の代役・代役の手際/丁寧さを追加。雇用する場合は実際のRecruitmentManager.Hireを使い、費用と日給を支払う。内勤が0人の方針では、Editor専用の代役が既存のCookingManagerを使って自動調理する。代役は名簿・日給・セーブに入らず、Playerビルドにも入れない。標準は手際0.5・丁寧さ0.5。専用の計算式は作っていない。代役・実調理・日給除外・片付けの5項目が通過。

J（内勤1人/設備なし）、K（1人/設備あり）、L（2人/設備あり）を同じ街シード1401・注文/事故シード20261022・3街区固定・目安60秒・通常資金で30日を上限として測定。Lの2人は比較の初期条件として能力をそろえて配置しており、2人目の採用費用は追加していない。日給は2人とも実際の式で負担する。これは内勤人数の効果を切り分ける判断で、通常ゲームで追加雇用が無料になる実装ではない。名簿上限の取り合いは、最新指示の人数上限撤廃に従って存在しない。
