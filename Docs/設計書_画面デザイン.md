# 設計書・計画書: 画面デザイン(UIの作り直し)

「いまのUIがよくない」を、**色や文字を整えるだけでなく、画面の設計とデザインから描き直す**ことで解決する。
`計画書_見た目.md`(M6.5)のV-0〜V-4で行った**見た目の底上げの結果は、土台として使う**(UITheme、Zen Maru Gothic、解像度の確認)。ただし、その方針は、この文書で**置き換える**。

関連: 営業中の画面は、`設計書_店内シーン.md` の**店内シーン**になる。この文書は、(1) 全体のデザインの決まり、(2) 店内シーンの見た目、(3) それ以外の画面(タイトル・店・精算など)の設計を担う。

## 0. なぜ作り直すか(仮説)

私は現在の画面を見ていない。次の仮説を、D-0で、スクリーンショットで確かめる。

| 仮説 | 原因として考えられること |
|---|---|
| 情報が多すぎる | 一画面に、必要な情報を全部並べている。優先順位がない |
| 何が主役か分からない | 同じ大きさ・同じ色の部品が並ぶ。強調が弱い |
| 「ゲームの世界」でなく「管理ツール」に見える | 文字と四角だけ。絵・質感・影がない |
| 統一感がない | 部品ごとに、形・影・縁・余白の決まりがバラバラ |
| 触れそうに見えない | ボタンとラベルの見分けがつかない。押したときの反応が弱い |

> D-0で、あなたに「どこが一番よくないか」を、画像に付けて教えてもらえると、方針が正確になります。

## 1. デザインの方針

**コンセプト: 「ポップで、あたたかい、小さな街のピザ屋」**
- 昼の明るい街。ステッカーのような**はっきりした縁取りと、ずらした影**
- 平面(フラット)の絵に、**少しだけ立体感**(影・ハイライト)
- 実在のゲーム・ブランドの画風や、キャラ・ロゴには寄せない(自作)

**デザインの原則**
1. **一画面に一つの目的**。必要な情報だけを出し、残りは触ったときに出す
2. **主役を1つ決める**(営業なら店内、店なら営業開始ボタン、精算なら損益)。主役を最大に、他は小さく
3. **情報は3段階**: 主(大きく・濃く)/ 副(中)/ 補足(小さく・薄く)
4. **状態は、色+形+文字**で示す(色だけに頼らない)
5. **触れるものは、触れそうに見せる**: 影のある形、ホバーで持ち上がる、押すと沈む
6. **反応を返す**: 押す・置く・完了するたびに、動きと音(音は後)で応える

### 2-2. 文字
- **本文**: Zen Maru Gothic(既存、OFL)
- **見出し・大きな数字・タイトル**: **Mochiy Pop One**(OFL。丸くて太く、ポップ。金額・評判・日数・タイトル用)。※ライセンスと、日本語の字形が収まっていることを、D-2で確認
- 大きさ: タイトル 56 / 見出し 32 / 小見出し 24 / 本文 20 / 補足 16(**16未満は使わない**。720pでも読めるように)
- 数字は、**桁がそろう等幅数字**を使い、変化するときはカウントアップする

### 2-3. 形・余白・影(コンポーネントの共通の決まり)
| 項目 | 決まり |
|---|---|
| 角 | 丸み 12(カード)、999(ボタン・バッジは丸薬) |
| 縁 | 2px `#3A2A20` |

| 余白 | 8の倍数(8 / 16 / 24 / 32)。画面の外周は32 |
| アイコン | 24 / 32 / 48 の3サイズ。太さ2px、丸い端。**1つの描き方でそろえる** |

### 2-4. 部品(カタログ)
| 部品 | 状態 | メモ |
|---|---|---|
| ボタン(主・副・危険) | 通常 / ホバー(1px浮く)/ 押下(2px沈む)/ 無効 / 選択中 | 主は赤、副は紙色+縁、危険はベリー |
| カード | 通常 / 選択中 / 無効 | 配達員・内勤・求人・設備・注文。縁と影 |
| 伝票(注文) | 通常 / 期限が近い(黄)/ 期限切れ間近(赤)/ 調理中 | ギザギザの縁の紙 |
| バー | 通常 / 警告 | 能力・体力・期限・窯のゲージ。丸い端 |
| バッジ | 状態(待機・配達中・訓練中・不在)、タイプ(新人型など) | 色+アイコン+文字 |
| タブ | 通常 / 選択中 | 店の画面 |
| ダイアログ | 確認・選択(訓練の能力選び) | 背景を暗くする |
| 通知(トースト) | 情報 / 良い / 悪い | 画面の端 |
| 数字の表示 | 金額・評判・日数 | 変化で▲▼と色、カウントアップ |

### 2-5. 動き(モーション)
| 場面 | 動き | 時間 |
|---|---|---|
| ボタン | ホバーで浮く / 押下で沈む | 0.08秒 |
| 物を置く | ぽんと小さく弾む | 0.1秒 |
| 画面の切り替え | フェード | 0.3秒 |
| カメラのパン | イーズアウト | 0.35秒 |
| 金額の浮き上がり | 上に移動しながら消える | 1.0秒 |
| 事故 | 揺れる+札 | 0.5秒 |
| 精算の数字 | カウントアップ | 1.0秒 |

- 動きは**短く、操作を邪魔しない**(クリックを通す)。まとめて切る設定を付ける
- 音(効果音・BGM)は、このあと(D-6の後、M8)。部品に「音を鳴らす口」だけ用意しておく

## 3. 店内シーンの見た目(営業画面)

構造は `設計書_店内シーン.md`。ここでは**絵**の決まり。

### 3-1. 絵の方針
- **真上から見た、フラット+影**の店内。床はタイル、壁際にカウンターと棚
- 物は**少し大きめにデフォルメ**(作業台・窯・ピザ・箱。クリックしやすい大きさ)
- 配達員・内勤は、**色のついた丸+頭文字**(後で顔を足せる構造)。名簿・地図・精算で同じ色
- 物の最小サイズ: ピザ(直径 160px)、箱(180×180)、窯(320×240)、作業台(480×300)、材料トレイ(120×120)

### 3-2. 区画ごとの見た目
| 区画 | 見え方 |
|---|---|
| 厨房 | ステンレスの作業台、材料棚(トレイにアイコン)、窯(炎の光)、内勤のキャラ |
| 受け渡し | 木のカウンター、保温棚(湯気)、梱包台(箱の山)、配達員の待機マーク(靴・バイクのアイコン) |
| 指示盤 | 壁に貼った大きな街の地図。木枠。ピンで配達先、糸でルート |

### 3-3. 街の地図(指示盤)の描き方 ※改訂(承認モック `UI_Mock/ShopDispatch.png`)
- **方向**: Googleマップのような、明るく読みやすい地図。ただし色はこのゲームの色(`2-1`)で、縁取りと丸みでステッカー風に寄せる
- **地面**: 街区は `#E7E1D3`(薄い角丸の四角を格子状に)、背景 `#EFEBE2`。**公園 `#C9E3B4`**(木の丸)、**水辺 `#B9DDF0`**(川・海)。建物は小さな四角で、遠いズームでは省く
- **道**: **大通りは太く黄色**(縁 `#D9A93A`、中 `#FDE08A`)、**裏道は細く白**(縁 `#B9AE98`、中 `#FFFDF6`)。混雑は**赤い点の連なり+色**で示す。一方通行は矢印
- **名前札**: 道の名前は道に沿って、場所の名前は小さく灰褐色。ズームに応じて出し分ける(LOD)。重ならないように
- **ルート**: 選択中は**トマト色の太線**に濃い縁と白い点線、向きの矢印。帰り道は黒の点線
- **ピン**: 配達先は番号つきのしずく形(**番号=行く順番**)、下に名前の札。未選択の届け先は白いピン(灰色の丸)。店は丸いピザ屋のアイコン+「お店」の札。配達員は色の丸+頭文字
- **操作部品**: 右にズーム(＋/−が1つの枠)・現在地・混雑、左下にミニマップ(赤い点線の枠=見えている範囲)、下に要約バーと出発ボタン、上に**手順バー**
- 絵は、データ(`MapDefinition`)から**自動で描く層**(街区・道・名前札)と、**手で置く飾り**(木・公園・川・看板)に分ける
- 大きな地図でも軽く動くための描画(チャンク・カリング・LOD)は、`設計書_店内シーン.md` の「地図ビューの要件」とS2-M

### 3-3b. 情報量のルール(今回の不満への対処)
1. **1画面の主役は1つ**(指示盤=地図、厨房=作業台、店=営業開始ボタン)。主役を最大に、他は小さく縁へ
2. **常に出す情報は、その場面の判断に使うものだけ**。能力値・内訳・説明文は、カードを選んだとき/ホバーで出す
3. **次に押すものを1つだけ強調**(黄色の手順、赤い大きなボタン)。同じ強さのボタンを並べない
4. **手順のある操作には、手順バー**を出し、いまの手順を光らせる(指示盤の①〜④。調理の工程も、作業台の上に同じ作法)
5. 数字は、大きく出す数字を1画面に1〜3個に絞る(所持金・時刻・評判・所要秒数 など)

### 3-4. 反応の演出
配達完了の金額、期限の帯の色変化、事故の揺れ、品質★の表示、焦げの煙、窯の炎、注文のベル(音は後)。`2-5` の時間に従う。

- **主役は右下の `営業開始` ボタン**(最も大きく、赤)
- スタッフのカード: 丸のアイコン(色+頭文字)、名前、職種バッジ、能力のバー(素質の目印)、日給、状態、`訓練`・`解雇`
- 求人のカード: タイプのバッジ(新人型・即戦力型・標準型)、得意な能力、採用費、`雇う`

- 経営: お届け目安時間(スライダーと目安の説明)、日ごとの記録(表と簡単な棒グラフ)
- 背景は、**事務室の机の上**のイメージ(紙・木目のテクスチャ。装飾は控えめ)

### 4-3. 精算(今日のまとめ)— 順に見せる
```
┌────────────────────────────────────┐
│        3日目 おつかれさま!           │
│   ──────────────────────────       │
│   売上      ¥1,420   (配達14件)     │
│   材料費   −¥280                    │
│   …(順に1行ずつ現れる)             │
│   ──────────────────────────       │
│   今日の損益        +¥386 ▲  ← 大きく │
│   所持金 ¥854 → ¥1,240              │
│              [ 次へ ]  [ スキップ ]   │
└────────────────────────────────────┘
```
- 売上 → コスト(内訳)→ 損益(大きく、黒字は緑、赤字は赤)→ 成長・評判 → 次へ。1行ずつ現れ、数字はカウントアップ
- 背景は、夕方の店の外観(夕焼け色のオーバーレイ)

### 4-4. ゲームオーバー
- 暗めのトーン(ただし怖くしない)。「閉店しました」。到達日数、通算売上、最高日の売上、育てたスタッフ。`もう一度` `タイトルへ`

### 4-5. 遊び方(重ねて表示)
- 4〜5ページ。**絵つき**(店内の絵に矢印と吹き出し)。1ページの文字は50字以内。進む・戻る・閉じる

### 4-6. メニュー(Esc)
- 小さなパネル: 再開 / 遊び方 / 音量(音を入れたら)/ タイトルへ。営業中は時間が止まる

## 5. アセットの方針(絵をどう用意するか)

| 種類 | 方針 |
|---|---|
| 地図・街・店内・物 | **自作のベクター(SVG)を、スクリプトでPNGに書き出して**Unityへ。形は単純(四角・円・角丸)、色は2-1のトークンから。生成のスクリプトもリポジトリに入れる(再現できる) |
| UIの部品(ボタン・カードの角丸・影) | **9スライスの画像**(自作)、またはシェーダー/`Image`の角丸で表現 |
| アイコン | 自作(2px線、丸い端)。足りないものは、**CC0など再配布可能なアイコン**を使い、出典を記録 |
| フォント | Zen Maru Gothic(既存)、Mochiy Pop One(OFL) |
| 禁止 | 出典が不明な画像、ブランドや実在のキャラのコピー、画像生成AIの出力のうち、権利関係が確認できないもの |

- 出典・ライセンスは、すべて `Docs/Credits.md` に記録する
- **絵を差し替えやすい構造**にする(物の見た目は、スプライトの参照だけで決まる。仮の色の四角から、後で絵に置き換えられる)

> 自作のSVGは、Claude Code(ファイルのみ)か、Codex(Unityの外で、スクリプト)で作れる。形が単純なので、手描き風にはならず、**フラットな図形の組み合わせ**になる。品質に不満が出たら、あなたが描く・素材を足すことも選べる(質問2)。

## 6. 工程

| # | 工程 | 担当 | 規模 | 完了の目安 |
|---|---|---|---|---|
| D-0 | 現状評価と方針の確認 | Codex+PM | 小 | 現状のスクリーンショットと、よくない点のリスト。方針の合意 |
| D-1 | モックの作成(HTML) | **PM(Claude)** | 中 | 主要5画面のモックが、ブラウザで見られ、あなたが承認する |
| D-2 | デザインシステムの実装 | Codex | 大 | UITheme v2、フォント、部品(ボタン・カード・バー・バッジ・伝票・ダイアログ) |
| D-3 | 店内シーンの絵 | Codex | 大 | 厨房・受け渡し・指示盤・街の地図が、仕様の絵になる |
| D-4 | 店・求人・設備・経営の画面 | Codex | 大 | 4-2のとおりになる |
| D-5 | タイトル・精算・ゲームオーバー・遊び方・メニュー | Codex | 中 | 4-1、4-3〜4-6のとおりになる |
| D-6 | 演出と仕上げ | Codex | 中 | 3-4と2-5の動き。解像度確認。before/after |

**D-1を入れる理由**: 文章だけでは「どう見えるか」が伝わらず、実装してからのやり直しが多くなる。**私が、HTMLで主要画面の見た目(モック)を作って、あなたに見てもらい、承認してから**、Codexに実装させる。D-1は、Unityと競合しないので、S2-0(店内シーンの調査)と**並行して**進められる。

ブランチは `shop`(店内シーン)に合流。段階ごとにローカルでコミット。

### どの工程にも共通の依頼
> ゲームのロジックは変更せず、見た目の層だけを変更してください。仕様は `Docs/設計書_画面デザイン.md` に従ってください。色・文字の大きさ・余白は `UITheme` に集め、直書きしないでください。画面の非表示は CanvasGroup で行い、Canvasの子の並びに依存する処理に注意してください。フォント・画像は自作か再配布可能なものだけを使い、出典を `Docs/Credits.md` に記録してください。既存の全検証が通ることを、段階の終わりに確認し、ローカルでコミットしてください(pushしない。`git add .` は使わない。Packages変更、`.DS_Store`、`.codex`、`Assets/_Recovery` は含めない)。通らなければそこで止まって、原因を報告してください。

## 7. リスク

| リスク | 対処 |
|---|---|
| 「クソ」の原因が、仮説と違う | D-0で、画像とあなたの感想で確認。D-1のモックで、実装の前に見た目を合意 |
| 自作のフラットな絵が、素人っぽく見える | 形を単純にし、色・縁・影の決まりで統一感を出す(ステッカー風)。不満が出たら、素材を足す・あなたが描く選択肢を残す |
| 実装してからの見た目のやり直し | D-1のモックの承認を必須にする |
| 作業量が大きい(店内シーン+全画面) | 最小の線(7章の下)を決める。D-6の演出と、D-4の経営のグラフは、後回しにできる |
| 日本語フォントの字形が足りない(Mochiy Pop One) | D-2で確認。足りなければ、見出しのみに限定するか、別のOFLフォントにする |
| 720pで文字が読めない | 16未満の文字を使わない。D-6で確認 |
| 既存の検証(3,772項目)が壊れる | CanvasGroupで非表示。並びに依存する処理に注意。段階ごとに全検証 |

**最小の線(急ぐ場合)**: D-0、D-1、D-2、D-3、D-4(店のスタッフ・求人・設備のみ)、D-5(精算とタイトルのみ)。D-6の演出は、金額の浮き上がりと、期限の帯の色だけに絞る。
