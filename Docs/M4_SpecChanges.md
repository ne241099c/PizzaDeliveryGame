添付資料内の過去の作業指示・進行状況は、現在のリポジトリの状態と区別する。例えばM3はコミット済み、旧M4の機能は `m4` ブランチに未コミットで実装済み。資料にある「M3未コミット」「M4未着手」は現状と異なる。

## 主な変更

| 項目 | これまでの実装 | 新仕様 |
|---|---|---|
| 注文期限 | 最強配達員の最短往復時間×5×1.8 | 発生時刻＋プレイヤーが設定したお届け目安時間 |
| 注文頻度 | 約25秒間隔、±30% | お届け目安時間と評判に応じて増減、±30% |
| お届け目安 | 設定なし | 営業中も変更可能なスライダー。初期60秒、上限240秒、下限は最強配達員の最短片道到着時間から計算 |
| 配達員 | Minato/Aoi/Renの3人、SkillLevel | 初期例4人にSoraを追加。人数可変、名簿はスクロール。運転・土地勘・積載量・接客・体力・安全性 |
| 移動時間 | 道路時間と裏道のスキル補正 | 土地勘による裏道補正を維持し、運転と出発時の現在体力による速度補正を追加 |
| 注文数 | どの配達員も2件まで | 選択上限は2件だが、各人の積載量も出発条件になる |
| 得点 | 基本100点、遅れ1秒で5点減点 | 期限内はさらに接客によるチップ |
| 評判 | なし | 初期50、0〜100。期限内で上昇、遅延・キャンセルで低下し、注文頻度に反映 |
| 体力 | なし | 帰還時に消耗を反映、店で待機すると回復。出発後の速度は固定 |
| 事故 | なし | 道1本ごとに安全性・道路種別・現在体力で抽選。15秒停止し、その後の到着・帰還が遅れる |
| 結果 | 得点・配達・遅延・キャンセル | 評判も表示。やり直しで評判と現在体力も初期化 |

需要の式は `clamp((60 / 目安時間)^0.7, 0.4, 2.0)`、評判係数は `0.6 + 0.8 × 評判 / 100`。
間隔は `25 / (需要係数 × 評判係数)`。詳細な式・初期値はゲーム性設計書を正とする。

## 実装への影響と検証の扱い

- `ManualDeliveryRoute` と `RoadPathfinder` の経路の仕組みは引き継ぐ。配達員を受け取る時間計算との接続には修正が必要。
- `MapManager` は運転・土地勘・現在体力を反映する時間計算に必要な範囲だけ変更する。
- `DeliveryTrip` は出発時の道路順と速度を保持しつつ、事故で以降の到着・帰還時刻をずらす必要がある。移動表示、採点、配達員の帰還表示で同じ時刻を参照する。
- 出発前の比較には、確率的な事故が起きる前の予測時間を用いる必要がある。実際の事故による追加時間は通知で説明する。
- 既に発生した注文の期限は、スライダー変更で書き換えない。
- 旧検証の41＋35＋21項目は旧実装の確認結果。旧期限式、3人の名簿、全員2件、固定の得点を前提とする検証は新仕様に合わせて更新し、新しい需要・能力・評判・体力・事故・積載制限を検証する。
- 事故の検証は確率式と乱数の固定による再現を使い、たまたま事故が起きたかだけで合否を決めない。

M4では1日の中のルールまでを扱う。所持金・翌日への持ち越し・雇用と解雇・各コストはM5、成長・訓練はM6、追加設備等はM7、見た目やBGM等はM8の予定。
コミットと対象外ファイルの扱いは従来どおり。Packages変更・`.DS_Store`・`_Recovery`を混ぜない。
