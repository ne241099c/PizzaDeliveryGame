# 設計書: 経営(お金・配達員の雇用と成長・コスト)

`設計書_ゲーム性.md` の「1日の中のルール」の上に、**日をまたぐ経営**を載せる。
配達員を雇う・首にする・育てる、お金を稼いで使う、コストを払う、という循環を定義する。

## 1. 確定事項

| 項目 | 決定 |
|---|---|
| 進行の形 | 終わりなしで続ける経営(資金が尽きたら終了) |
| お金と得点 | 得点がそのままお金(売上) |
| 配達員の成長 | 経験による自動成長 + お金を払う訓練の両方 |
| コスト | 日給のほかにも複数(3章) |

## 2. 1日のサイクル

```
[開店準備] 雇用 / 解雇 / 訓練の指示(お金を使う)
   ↓
[営業] 設計書_ゲーム性.md のとおり(注文・配達・得点=売上)
   ↓
[閉店・精算] 収入 − コスト = その日の損益 → 所持金に反映
   ↓
 所持金がマイナスならゲームオーバー(破産)。そうでなければ翌日の開店準備へ
```

- 精算画面には、収入と、コストの内訳(3章の各項目)を並べて見せる。どこで赤字になったかが分かるようにする
- 破産は「精算後の所持金が0未満」とする。営業中は一時的にマイナスになってもよい
- 開店準備では時間は進まない(落ち着いて判断できる)

## 3. コスト(初期値は全てたたき台)

お金の単位は得点と同じ(1件の基本点=100)。

| コスト | いつ発生 | 初期値 | ねらい |
|---|---|---|---|
| 日給 | 毎日の精算時、配達員ごと | `50 + 40 × (運転+土地勘+接客+体力+安全性) + 30 × (積載量−1)` | 雇うほど毎日の負担が増える。能力が高い人は高い |
| 材料費 | 配達員が出発した時、注文1件ごと | 20 | 出発しなければ発生しない |
| 燃料費 | 配達員の移動した距離に応じて、精算時 | `距離 × 0.4` | まとめて回るほど安く済む(効率の判断を後押し) |
| 固定費(家賃・光熱費) | 毎日の精算時 | 150 | 注文が少なくても必ず出ていく |
| 採用費 | 雇った時に1回 | 日給の3日分 | 雇用に一回分の覚悟が要る |
| 解雇手当 | 解雇した時に1回 | 日給の1日分 | 気軽に入れ替えられないようにする |
| 訓練費 | 訓練を指示した時 | `150 + 400 × スキル` | 高スキルほど高い(5章) |

目安として、1日の売上上限は約1,200(営業5分・注文約12件・満点の場合)。
配達員3人でコストが約700前後(日給約420 + 固定費150 + 材料費・燃料費)に収まるように始める。
黒字になるかぎりぎりのところから始めて、遊んで調整する。

### 追加の候補(後回し・M7以降)
最初から全部入れず、基本のコストで遊べると確認してから足す。

| 候補 | 内容 |
|---|---|
| 事故の修理費 | 事故(設計書_ゲーム性.md 6章。M4で実装)が起きたときの修理費。M4では停止のみで、お金は絡まない |
| 広告費 | 払うと注文の発生間隔が短くなる(売上を伸ばす投資) |
| 設備投資 | 配達員の枠を増やす、店舗を広げる(固定費も上がる) |
| 車両 | バイクの性能で移動速度が変わる(購入費・維持費) |

## 4. 配達員の雇用と解雇

### 雇用
- 開店準備で「求人」を開くと、**毎日ランダムに2〜3人の候補**が並ぶ
- 候補ごとに、名前・**6つの能力**(運転・土地勘・積載量・接客・体力・安全性)・**素質(各能力の上限)**・日給・採用費を表示する
- 候補は、**得意と不得意がはっきりした人**が出るようにする(全部が平均的な人は出にくい)。例: 速いが危うい、遅いが丁寧でタフ
- 素質が高い人は今は能力が低くても、育てれば伸びる。**今強い人を雇うか、安い新人を育てるか**が判断になる
- **人数は固定しない。** 名簿に何人でも入れられる。ただし、同時に管理できる人数の上限は初期4人にして、広げるのは設備投資とする(後回し)

### 解雇
- 開店準備で解雇でき、解雇手当を払う
- 配達中・訓練中の配達員は解雇できない

### 開始時
- 配達員 2人(Aoi、Ren。能力は設計書_ゲーム性.md 6章の例)から始める。MinatoとSoraは求人に出てくる候補にする
- 開始資金 300(初期値)

## 5. 配達員の成長

配達員の能力は6つ(運転・土地勘・積載量・接客・体力・安全性。設計書_ゲーム性.md 6章)。
成長は、**使った能力が育つ**形にする。**具体的な式と数値は `計画書_M6.md` を正とする**(以下は方針)。

### 経験による自動成長
- 配達を重ねると、使った能力に経験が貯まり、一定量でその能力が少し上がる(素質が上限)
  - 運転: 走った距離 / 土地勘: 裏道を走った回数 / 接客: 期限内に届けた数 / 体力: 働いた時間 / 安全性: 事故なく走った回数
  - 積載量は経験では育たない(訓練のみ)
- 使えば使うほど育つので、**よく働く人が、働き方に応じた方向に育つ**

### 訓練(お金で成長)
- 開店準備で、配達員と**伸ばしたい能力を1つ選んで**訓練を指示する(訓練費を払う)
- 訓練した配達員は**営業時間の前半だけ営業に出られない**(M5の測定で、丸1日休むと2人編成では損が大きすぎると分かったため改訂。比率は調整項目)。前半が終わった時点でその能力が +0.1(素質が上限。積載量は +1)。詳細は `計画書_M6.md`
- 訓練中の日給は通常どおり払う。育てている間の稼ぎがなくなる、というコストが「判断」になる

### 配達員のデータ
| フィールド | 内容 |
|---|---|
| Id / Name | 識別子と名前 |
| 6つの能力 | 運転・土地勘・接客・体力・安全性(0〜上限)、積載量(整数) |
| 素質 | 各能力の上限 |
| 経験値 | 能力ごとの蓄積 |
| DailyWage | 日給(能力から計算) |
| Status | Idle / Delivering / Returning / Training(営業に出られない) |
| 現在体力 | 営業中の疲れ(M4で実装) |

## 6. 画面の追加

| 画面 | 内容 |
|---|---|
| 開店準備 | 所持金、評判、配達員の一覧(6能力・素質・経験・日給)、雇用・解雇・訓練の操作、求人の候補 |
| 精算 | 収入と、コストの内訳、その日の損益、所持金の変化 |
| ゲームオーバー | 破産。到達した日数、通算の売上、育てた配達員を表示 |

## 7. 開発の順序(提案)

作る量が大きいので、**段階を分けて、早く遊べる状態にする**。

| マイルストーン | 内容 |
|---|---|
| M4 | ゲーム性の成立(時間・注文・期限・並行配達・得点)。設計書_ゲーム性.md |
| M5 | 経営の土台: 所持金、日をまたぐサイクル(評判も持ち越す)、精算画面、日給・材料費・燃料費・固定費、破産。**配達員の雇用・解雇**(名簿が変わる。固定の人数ではなくなる) |
| M6 | 配達員の成長: 経験による成長、訓練、素質、求人の個性(得意・不得意のある候補の生成) |
| M7 | 追加コスト・設備(事故、広告、設備投資、車両)。必要かを遊んで判断してから |
| M8 | 厚み付け(旧M5。ピザ作成ミニゲーム、マップの見た目、BGM、ランキングなど) |

M4の次にM5まで作ると「稼いで払って、赤字なら終わる」という最小の経営ゲームとして遊べる。
雇用・成長(M6)はその上に載せる。

## 8. 気をつけること
- **範囲が大きい。** M4〜M6でそれぞれ数日分の作業になる。応募の期限が決まったら、M5までで一度完成とみなし、M6以降を見送る判断もありうる
- **終わりなしの経営は、バランス調整が重い。** コストと売上の釣り合いが少し崩れると、すぐ破産するか、いつまでも破産しなくなる。数値は必ず調整項目にする
- **完全リアルタイムの営業に、準備画面と精算画面が加わる。** 画面数が増えるので、M4-0(UIをScene上の実体にする)を先に済ませておく
- 求人のランダム生成は、能力・素質・日給が釣り合い、かつ得意不得意が出るよう、生成ルールを決める必要がある(M6の設計で詰める)

## 9. 未確定・遊んで決めること
- 開始資金、各コストの金額、日給の計算式
- 訓練中の配達員の日給は払うか(現状は払う)
- 破産の猶予(例: 1日だけ猶予を与える)を入れるか
- 難易度が日を追って上がる仕組み(注文の増加、期限の短縮)の要否
- セーブ・ロード(日をまたぐので、いずれ必要)
