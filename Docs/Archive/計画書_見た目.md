# 計画書: 見た目の底上げ(M6.5)

M6(成長・訓練・求人・セーブ)と、**画面構成の再編(`設計書_画面構成.md` のS-0〜S-5)が終わった後**に行う。**機能は変えず、見た目だけを整える。**
(画面構成が先。画面が場面ごとに分かれてから、`UITheme` を各画面に適用する。V-0 の「全画面の一覧」は、S-5 まで終えた画面を対象にする。ブランチは `screens` を統合した `main` から `ui` を作る)
目的: 開発用の画面を、**初めて見る人にも伝わる、まとまった画面**にする。応募で見る人は、説明なしで触る。最初の10秒で印象が決まる。

## 0. 範囲

### やること(この計画書の対象)
1. **配色・フォント・余白の統一**(全画面)
2. **地図の見た目**(背景・道・アイコン・配達員の表示)
3. **出来事への反応の表示**(金額の浮き上がり、期限の色、事故の演出)
4. 仕上げ(解像度、重なりの確認、前後の比較画像)
5. (任意)人らしさ: 配達員のアイコンと、客の名前・一言

### やらないこと(あとの仕上げに回す)
BGM・効果音、タイトル画面、ピザ作りミニゲーム、遊び方の説明、キャラの絵、配達員の細かいアニメーション

### 守ること
- **ゲームのロジックは変えない。** 見た目の層だけを変える。既存の検証(M5の337項目 + M6の分)が、すべて通り続けること
- **Canvasの子の並びを勝手に変えない。** M5-2で、末尾に部品を足しただけで既存検証が壊れた(DayResultsが最後の兄弟でなくなった)。並びに依存する処理があるので、並びを変えたら必ず検証を回す
- 画像・フォントは、**自作か、再配布できるライセンスのもの**だけを使う。出典とライセンスを `Docs/Credits.md` に残す
- 色・文字の大きさ・余白は、**1か所の設定(UITheme)にまとめ**、画面ごとに数値を直書きしない

## 1. デザインの方針

**コンセプト: 「あたたかい街の、小さなピザ屋」。** 明るくて見やすく、数字の多い画面でも疲れないこと。

### 色(UITheme で定義。初期値は下の案)
| 役割 | 色 | 使いどころ |
|---|---|---|
| 地(背景) | `#FBF3E4` クリーム | パネルの背景 |
| 文字 | `#2B2118` こげ茶 | 本文 |
| 主役(アクセント) | `#D8452B` トマト赤 | 主なボタン、選択中、強調 |
| 良い | `#4C8C4A` バジル緑 | 期限内、黒字、成功 |
| お金・注意 | `#F2B632` チーズ黄 | 売上、チップ、期限が近い |
| 悪い | `#B3261E` 深い赤 | 遅れ、赤字、事故、破産 |
| 補助 | `#8A7A66` | 無効なボタン、小さな説明 |
| 地図の街区 | `#E6D5B8` | 建物の塊 |
| 地図の公園 | `#BFD8A8` | 空き地(任意) |

- 良い・悪い・注意は**色だけに頼らず、記号か文字も付ける**(▲▼、「遅れ」など)

### 文字
- 日本語が読みやすい丸ゴシック系の、**再配布できるフォント**を使う(例: M PLUS Rounded 1c、Zen Maru Gothic。ともにOFLライセンス)。TextMeshProのフォントアセットを作り、動的に使う
- 大きさ: 見出し 28 / 小見出し 22 / 本文 18 / 補足 14(これ以下にしない)。UITheme で定義
- 数字(金額・評判)は、桁がそろって見やすいように、同じフォントで少し大きめ・太めにする
- **文言は日本語に統一する**(いまは英語が混ざっている: `Delivery promise` `Start business` `Next day` など)。応募先を考えて日本語を標準にする。必要なら、あとで英語に切り替えられるよう、文言は一か所にまとめる(完全な多言語化まではしない)

### 余白・形
- 余白は 8 の倍数(8 / 16 / 24)。パネルの内側は 16
- 角は丸く(半径 8)。パネルに薄い影か縁を付けて、地図と区別する
- 1画面に、強調するものは**1〜2個まで**(主なボタンと、一番大事な数字)

### ボタンの種類(すべてのボタンがこのどれか)
| 種類 | 見た目 | 例 |
|---|---|---|
| 主 | トマト赤の塗り、白い文字 | 営業開始、出発 |
| 副 | 縁だけ、茶色の文字 | 訓練を取り消す、リセット |
| 危険 | 深い赤 | 解雇、最初から |
| 無効 | 灰色、薄い文字。**理由を近くに表示** | 資金不足の採用 |
| 選択中 | アクセントの縁と薄い赤の背景 | 選んだ配達員・注文 |

## V-0: 現状の調査と土台

**仕様**
- 画面の一覧を作る(営業中・開店準備・精算・ゲームオーバー・求人・訓練・セーブ選択、など。M6の分を含む)。それぞれの**現在のスクリーンショット**を `Docs/UI_Screens/before/` に保存する
- 画面ごとに、使っている色・文字の大きさ・フォントを調べて一覧にする(直書きの場所を洗い出す)
- `UITheme`(ScriptableObject)を作り、1章の色・文字の大きさ・余白・角の丸みを入れる
- UITheme を読んで、見た目を適用する小さな部品を作る(例: `ThemedText` `ThemedButton` `ThemedPanel`)。ボタンの5種類(主・副・危険・無効・選択中)に対応する
- 日本語フォントのTextMeshProフォントアセットを作る

**完了条件**: 画面一覧と before 画像がある。UITheme を変えると、部品を付けたテストの画面の見た目が変わる。検証がすべて通る。

**指示文**
> 現在のすべての画面(営業中、開店準備、精算、ゲームオーバー、求人、訓練、セーブ選択など)の一覧を作り、それぞれのスクリーンショットを `Docs/UI_Screens/before/` に保存してください。あわせて、画面ごとの色・文字の大きさ・フォントの直書き箇所を調べて、一覧にしてください。
> 次に、`UITheme`(ScriptableObject)を作ってください。色は、地 `#FBF3E4`、文字 `#2B2118`、アクセント `#D8452B`、良い `#4C8C4A`、お金・注意 `#F2B632`、悪い `#B3261E`、補助 `#8A7A66`、地図の街区 `#E6D5B8`、公園 `#BFD8A8`。文字の大きさは 見出し28 / 小見出し22 / 本文18 / 補足14。余白は8の倍数、角の丸みは8です。UITheme を読んで適用する小さな部品(`ThemedText`、`ThemedButton`(主・副・危険・無効・選択中の5種類)、`ThemedPanel`)を作ってください。日本語に対応した、再配布できるフォント(OFLなど)で TextMeshPro のフォントアセットを作ってください。出典は `Docs/Credits.md` に書いてください。まだ既存の画面には適用しないでください。

**学べること**: 見た目を1か所の設定(ScriptableObject)にまとめる方法。TextMeshProのフォントアセット。

## V-1: 配色・フォント・余白を全画面に適用

**仕様**
- V-0 の一覧の全画面に、部品と UITheme を適用する
- 文言を日本語に統一する(文言は1か所の文字表にまとめる)
- ボタンを5種類に分類して適用。無効のボタンには**理由を近くに表示**(すでにあるものは、見た目をそろえる)
- 配達員の6能力のバーを、色と太さをそろえる(素質の目印、経験値の進みも見やすく)。能力ごとに色を変えるか、同じ色でそろえるかは、見て決める
- 注文の一覧の行(期限の残りを帯で表示)、配達員の行(状態を色付きのバッジで)を整える
- 数字(所持金・評判・売上)は大きめ・太めにし、変化する数字には ▲▼ を付ける

**完了条件**: すべての画面で、色・文字・余白・ボタンの見た目がそろう。日本語の文言に統一されている。文字の重なりと、画面外へのはみ出しがない(スクロールする部分を除く)。検証がすべて通る。

**指示文**
> V-0 で作った `UITheme` と部品を、画面一覧のすべての画面に適用してください。文言は日本語に統一し、文言は1か所の文字表にまとめてください(完全な多言語化は不要)。ボタンは、主・副・危険・無効・選択中のどれかにしてください。無効のボタンには理由を近くに表示してください。配達員の6能力のバーは、色と太さをそろえ、素質の目印と経験値の進みが見やすいようにしてください。注文の行は期限の残りを帯で、配達員の行は状態を色付きのバッジで表示してください。所持金・評判・売上は大きめ・太めにし、変化する数字には ▲▼ を付けてください。段階の終わりに、各画面のスクリーンショットを `Docs/UI_Screens/after-v1/` に保存してください。

## V-2: 地図の見た目

**仕様**
地図のデータ(`MapDefinition`、ノードとエッジ)は変えず、**見た目の層**を足す。
- **背景**: 全体の地の色、街区(建物の塊の四角形。道に囲まれた部分を塗る)、公園(任意)。街区は、道の位置から自動で作るか、手で配置するデータ(別の設定)にするか、Codexが決めてよい。判断した点として報告する
- **道**: 太さと色で区別する。大通りは太く明るく、裏道は細く茶色寄り。縁取り線を付ける。**混雑(`TrafficFactor`)は色で見せる**(空いている=緑寄り、混んでいる=赤寄り。色だけでなく太さか模様も変える)。一方通行は矢印を付ける
- **場所の印**: 店(ピザ屋のアイコン)、配達先(家・アパートのアイコン)、交差点(小さな丸)。名前の札を付ける(重ならないように)
- **選択中のルート**: 太く、アクセントの色で強調。向きが分かるよう矢印を付ける
- **配達員の印**: 配達員ごとに色を変えた丸(頭文字を入れる)、進行方向が分かる向き。停止中(事故)は点滅か記号
- アイコンは、自作の簡単な形(シンプルな図形の組み合わせ)でよい。Unityの標準機能で描く

**完了条件**: 地図を見て、大通りと裏道、店、配達先、混雑の度合い、配達員の位置と色が区別できる。選択中のルートが目立つ。地図の拡大縮小・移動(既存)がそのまま動く。検証がすべて通る。

**指示文**
> 地図の見た目の層を追加してください。`MapDefinition` とロジックは変更しないでください。全体の背景色、街区(道に囲まれた部分を塗った四角形。手配置のデータか自動生成かは判断してください)を足してください。道は、大通りは太く明るく、裏道は細く茶色寄りにし、縁取り線を付けてください。混雑(TrafficFactor)は、空いている=緑寄り、混んでいる=赤寄りの色に加え、色だけに頼らず太さか模様でも区別してください。一方通行には矢印を付けてください。
> 店(ピザ屋のアイコン)、配達先(家・アパートのアイコン)、交差点(小さな丸)を表示し、名前の札は重ならないようにしてください。選択中のルートは太くアクセント色で、向きの矢印を付けて強調してください。配達員の印は、配達員ごとに色を変えた丸(頭文字入り)にし、進行方向が分かるようにしてください。事故で停止中は点滅か記号で示してください。アイコンは自作の単純な図形で構いません。既存の地図の拡大縮小・移動が動くことを確認し、スクリーンショットを `Docs/UI_Screens/after-v2/` に保存してください。

**学べること**: データ(地図の構造)と見た目を分ける設計。スプライトとシェイプの描き方。

## V-3: 出来事への反応の表示

**仕様**(Unityの標準機能だけで作る。追加パッケージは使わない)
- **配達完了**: 到着地点に、獲得額が浮き上がって消える(例: 「+105」)。期限内は緑、チップは黄色で「+チップ」、遅れは赤で減点を表示
- **期限の帯**: 注文の残り時間の帯の色が、緑 → 黄 → 赤 に変わる。期限が切れそうなものは目立たせる
- **事故**: 地図上の配達員の印が揺れ、「事故!」の札が出る。停止の残り秒数を表示
- **評判・所持金の変化**: 数字が変わるとき、▲▼ と色が一瞬付く。精算画面では、数字が増減する動きで見せる(カウントアップ)
- **営業時間の帯**: 残り時間が少なくなると色が変わる
- **配達員の体力**: 低い時に目立つ(バーの色、警告の記号)
- 演出は短く(0.5〜1.5秒)。**ゲームの操作を邪魔しない**(クリックを通す)。設定で演出を切れるようにする

**完了条件**: 配達完了・遅れ・事故・期限の接近が、数字を見なくても分かる。演出が操作を邪魔しない。検証がすべて通る。

**指示文**
> 出来事への反応の表示を追加してください(追加パッケージは使わず、コルーチンと AnimationCurve で作ってください)。配達完了時に、到着地点に獲得額が浮き上がって消える表示(期限内は緑、チップは黄色、遅れの減点は赤)を出してください。注文の期限の帯は、残り時間に応じて緑→黄→赤に変えてください。事故では、地図上の配達員の印が揺れ、「事故!」の札と停止の残り秒数を出してください。所持金と評判が変わるときは、▲▼と色を一瞬付け、精算画面では数字が増減する動き(カウントアップ)で見せてください。営業時間の残りが少ないときと、配達員の体力が低いときも、色や記号で目立たせてください。
> 演出は0.5〜1.5秒の短いものにし、クリックを妨げないでください(raycastの対象外にする)。演出をまとめて切る設定(Inspector)も作ってください。ロジックは変更しないでください。

## V-5(任意): 人らしさ

**仕様**
- **配達員のアイコン**: 色付きの丸に頭文字。名簿・地図・精算で同じ色を使う(V-2 の印と同じ)。気が向けば、顔のシンプルな絵(自作)
- **客の名前と一言**: 注文ごとに、客の名前(ランダム)と短い一言(例: 「お腹ペコペコです!」「急いでます!」)を表示。期限が短い注文は「急いでます」系にするなど、状況に合わせる。**ゲームのロジックは変えない**(見た目だけ)
- 配達完了時に、客の一言が返る(例: 「ありがとう!」。遅れた時は「遅いよ…」)

**完了条件**: 注文と配達員に「人」の気配が出る。検証がすべて通る。

**指示文**
> 配達員に、色付きの丸と頭文字のアイコンを付け、名簿・地図・精算で同じ色にそろえてください。注文には、客の名前(ランダム、乱数は固定して検証できるように)と短い一言(状況に合わせる。期限の短い注文は急いでいる一言など)を表示してください。配達完了時には客の一言(期限内は感謝、遅れたときは不満)を短く表示してください。ロジックは変更しないでください。文言は文字表にまとめ、日本語にしてください。
