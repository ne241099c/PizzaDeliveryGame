# M5 計画書: 経営の土台

元になる仕様: `設計書_経営.md`(お金・コスト・雇用の仕様)と `設計書_ゲーム性.md`(1日の中のルール)。
この計画書は、それをCodexに渡せる単位に分け、完了条件と指示文をつけたもの。仕様の式と初期値は設計書を正とする。

**M5のゴール**: 1日が終わると精算され、お金と評判と配達員が**翌日に持ち越され**、赤字が続くと破産で終わる。
開店準備で配達員を雇ったり解雇したりできる。つまり**「稼いで払って、赤字なら終わる」最小の経営ゲームとして遊べる**こと。

## 0. 前提と、M4からの引き継ぎ

- M4は`m4`ブランチに実装済み。M5の前に、`m4`を`main`へ統合し、M5用の新ブランチ(`m5`)を切る
- M4で人が遊んだ確認はしていない(自動検証のみ)。そのため、**M5の最後に、自動プレイで数値を測る仕組み(M5-6)を入れる**
- 数値(コスト・開始資金・係数)は、すべてInspectorで変えられるようにする。コストは、売上が分かってから調整する前提

## 1. M5で決めたこと(設計書を補う)

| 項目 | 決定 |
|---|---|
| 1日の区切り | 開店準備 → 営業 → 精算 → 次の日の開店準備。「もう一度」は、破産後の「最初から」に役割を変える |
| 開始時の状態 | 1日目。所持金300、評判50、配達員は2人(Aoi、Ren) |
| 持ち越すもの | 所持金、評判、配達員の名簿と能力、日数、通算の記録。**持ち越さないもの**: 注文、配達中の状態、現在体力(翌日は満タン)、その日の得点 |
| 売上 | その日に確定した得点(チップ込み、遅延の減点後)の合計 |
| 材料費 | 出発した時に、注文1件ごとに20。その場で所持金から引く(営業中にマイナスになってもよい) |
| 燃料費 | 配達員が通った道の距離の合計 × 0.4。精算時に引く(事故で止まっている間は増えない) |
| 日給 | 雇っている全員分。`50 + 40 × (運転+土地勘+接客+体力+安全性) + 30 × (積載量−1)`。精算時に引く |
| 固定費 | 毎日150。精算時に引く |
| 破産 | **精算後の所持金が0未満**でゲームオーバー(営業中のマイナスは許す)。猶予日数は調整項目にし、初期値は0 |
| 閉店時のキャンセル | 評判の低下は調整項目にし、**初期値は0**(M4の−5を改める) |
| 雇用 | 開店準備でのみ。採用費 = 日給の3日分。雇ったその日から営業に出られる |
| 解雇 | 開店準備でのみ。解雇手当 = 日給の1日分。最低1人は残す(0人にできない) |
| 人数の上限 | 雇える人数は最大4人(調整項目) |
| 求人 | 毎日ランダムに2〜3人。得意と不得意がはっきりした能力にする(下の生成ルール) |

### 求人の生成ルール(簡易版。M6で素質と合わせて作り直す)
- 名前: 用意した名前の一覧から、名簿・他の候補と重複しないように選ぶ
- 各能力(運転・土地勘・接客・体力・安全性)の基準値: 0.3〜0.7のランダム
- **得意2つ**に +0.2〜0.3、**不得意2つ**に −0.2〜0.3 する(0〜1に収める)。残り1つは基準値のまま
- 積載量: 50%で1、50%で2
- 日給は、上の式で能力から計算する。採用費は日給の3日分

## M5-1: 日の進行と持ち越し

**目的**: 1日が終わったら終わりではなく、翌日へつながる流れにする。

**仕様**
- フェーズ: `開店準備` → `営業` → `精算` → 次の日の `開店準備`。いまの「営業の開始」と「結果画面」の間に、前後のフェーズを入れる
- 日数(1日目から)を持ち、画面に表示する
- 精算の後、`次の日へ` で翌日の開店準備に進む。このとき:
  - **持ち越す**: 所持金、評判、配達員の名簿と能力、日数、通算の記録
  - **リセットする**: 注文、配達中の状態、現在体力(満タンに戻す)、その日の得点と集計、時計
- この段階では、開店準備の画面は「`営業開始` ボタンだけ」でよい(M5-5で中身を入れる)
- 現在の `Play again`(もう一度)は、**破産後の「最初から」**に使う(M5-4で接続)。M5-1の時点では、一時的に残してよい

**完了条件**
- 営業を終えて精算まで進み、`次の日へ` で2日目の開店準備になる。日数が増える
- 評判が翌日に持ち越される(1日目の終わりの評判から、2日目が始まる)
- 注文・配達中の状態・体力・その日の集計は、翌日にリセットされている
- 持ち越しとリセットの検証を追加する

**指示文**
> 1日の流れを、`開店準備` → `営業` → `精算` → 次の日の `開店準備` というフェーズの繰り返しにしてください。日数(1日目から)を持ち、画面に表示してください。結果画面の `Play again` は、翌日へ進む `次の日へ` ボタンに置き換え、次の日の開店準備に進むようにしてください(破産後の「最初から」は後で接続するため、いまは別の関数に切り出して残してください)。
> 翌日へ持ち越すのは、評判、配達員の名簿と能力、日数、通算の記録です(所持金は次の段階で追加します)。リセットするのは、注文、配達中の状態、現在体力(満タンに戻す)、その日の得点と集計、時計です。開店準備の画面には、いまは `営業開始` ボタンだけを置いてください。持ち越しとリセットの検証を追加してください。

**学べること**: ゲームの状態(フェーズ)を、永続するものと、毎日リセットするものに分ける設計。

## M5-2: 所持金と売上

**仕様**
- 所持金(開始300)を持ち、画面の上部に常に表示する

## M5-3: コスト

**仕様**(1章の決定どおり)
- **材料費**: 出発した時に、選んだ注文1件ごとに20を、その場で所持金から引く
- **燃料費**: 各配達員が通った道の距離の合計 × 0.4。事故で止まっている間は増えない。精算時に引く
- **日給**: 雇っている全員分、`50 + 40 × (運転+土地勘+接客+体力+安全性) + 30 × (積載量−1)`。精算時に引く
- **固定費**: 毎日150。精算時に引く
- その日のコストを、項目ごとに記録する(`DayLedger`)。精算画面で内訳として使う

**完了条件**
- 出発すると、材料費が即座に所持金から引かれる
- 精算で、日給・固定費・燃料費が引かれる。AoiとRenの日給は、式どおり(約220と約184)になる
- 燃料費が、実際に通った距離に比例する(同じ配達先でも、遠回りすると増える)
- 各コストの計算を検証に追加する

**指示文**
> 次のコストを実装してください。(1)材料費: 出発した時に、選んだ注文1件ごとに20を、その場で所持金から引く。(2)燃料費: 各配達員が通った道の距離の合計 × 0.4(事故で止まっている間は増えない)。精算時に引く。(3)日給: 雇っている全員分、`50 + 40 × (運転+土地勘+接客+体力+安全性) + 30 × (積載量−1)`。精算時に引く。(4)固定費: 毎日150。精算時に引く。
> その日のコストを項目ごとに記録するクラス `DayLedger` を作ってください(売上、材料費、燃料費、日給、固定費、損益)。各コストの計算を検証に追加してください。

**学べること**: お金の増減を1か所(台帳)に記録する設計。

## M5-4: 精算画面と破産

**仕様**
- 精算画面に、その日の**売上と、コストの内訳(材料費・燃料費・日給・固定費)、損益、所持金の変化**を並べる。どこで赤字になったかが分かるようにする
- 従来の結果(得点・配達数・遅延数・キャンセル数・評判・配達員ごとの積載量と残り体力)も、精算画面に残す
- **精算後の所持金が0未満**なら、`ゲームオーバー(破産)`画面に進む。表示するのは、到達した日数、通算の売上、最高の1日の売上。`最初から` で、1日目の初期状態(所持金300、評判50、配達員2人)に戻る
- 破産の猶予日数は調整項目にする(初期値0)

**完了条件**
- 精算画面の損益が、売上 − 各コストの合計と一致する
- 所持金が足りなくなる設定で、ゲームオーバーになり、`最初から` で初期状態に戻る
- 黒字なら、次の日に進める
- 破産の判定を検証に追加する

**指示文**
> 精算画面を作ってください。その日の売上と、コストの内訳(材料費・燃料費・日給・固定費)、損益、所持金の変化を並べて表示し、従来の結果(得点・配達数・遅延数・キャンセル数・評判・配達員ごとの積載量と残り体力)も残してください。
> 精算後の所持金が0未満(猶予日数を過ぎても)なら、ゲームオーバー画面(到達した日数、通算の売上、最高の1日の売上)に進み、`最初から` で1日目の初期状態(所持金300、評判50、配達員はAoiとRenの2人、日数1)に戻してください。猶予日数は調整項目(初期値0)にしてください。破産の判定を検証に追加してください。

## M5-5: 開店準備・雇用と解雇

**仕様**
- 開店準備の画面に、次を表示する: 所持金、評判、日数、配達員の名簿(6能力・日給)、求人の候補、`営業開始`ボタン
- **解雇**: 名簿の配達員を選んで解雇できる。解雇手当(日給の1日分)を払う。最後の1人は解雇できない
- **雇用**: 求人の候補から選んで雇える。採用費(日給の3日分)を払う。所持金が足りなければ雇えない(理由を表示)。人数の上限(初期4人)を超えて雇えない
- **求人**: 開店準備に入るたびに、毎日2〜3人をランダムに生成する(1章の生成ルール)。雇わなかった候補は、翌日に消える
- 開始時の名簿は2人(AoiとRen)。MinatoとSoraは、求人の候補の名前の一覧に入れる(能力はランダム。初期例の能力にはこだわらない)
- 名簿が変わっても、M4の画面(配達員の選択・一覧のスクロール)がそのまま動く

**完了条件**
- 開店準備で、求人から雇うと名簿が増え、所持金が減る。その日から営業に出せる
- 解雇すると名簿から消え、手当が引かれる。最後の1人は解雇できない
- 所持金不足・人数の上限・最後の1人の解雇は、理由つきで止められる
- 求人の生成が、仕様の範囲(能力が0〜1、得意不得意の差)に収まる(乱数を固定して検証)
- 雇った人の日給が、翌日の精算に入る

**指示文**
> 開店準備の画面を作ってください。所持金、評判、日数、配達員の名簿(6能力と日給)、求人の候補、`営業開始` ボタンを表示します。
> 解雇: 名簿の配達員を選んで解雇でき、解雇手当(日給の1日分)を払います。最後の1人は解雇できません。雇用: 求人の候補から選んで雇え、採用費(日給の3日分)を払います。所持金が足りないとき、雇える人数の上限(初期4人、Inspectorで変更可)を超えるときは、雇えず、理由を表示してください。
> 求人: 開店準備に入るたびに、毎日2〜3人をランダムに生成します。各能力(運転・土地勘・接客・体力・安全性)の基準値は0.3〜0.7のランダム、得意2つに +0.2〜0.3、不得意2つに −0.2〜0.3(0〜1に収める)、積載量は50%で1か2です。名前は、用意した一覧(Minato、Soraなどを含む)から、名簿や他の候補と重複しないように選んでください。雇わなかった候補は、翌日に消えます。
> 開始時の名簿は、AoiとRenの2人にしてください。名簿が変わっても、配達員の選択・一覧のスクロールなど、M4の画面が動くようにしてください。求人の生成は乱数を固定して検証してください。

**学べること**: ランダム生成に「制約」(得意と不得意)をかけて、面白さを作る方法。

## M5-6: 自動プレイ検証(数値の測定)

**目的**: 人が遊んでいない状態で、**コストと売上の釣り合いの目安**をつかむ。遊んで調整する(M4-9)代わりではなく、その前の当たりをつけるための道具。

**仕様**
- Unityのメニューに `Tools > Pizza Delivery > Simulate Days` を追加する(Playモードで実行)
- 指定した日数(初期10日)を、**自動で操作して回す**
  - 方針: 注文がある間、待機中の配達員のうち、積載量の許す人に、**`Dispatch with suggestion` と同じ推奨ルートで出発させる**(まず注文1件ずつ。同じ配達員の候補が複数あれば、期限が近い注文を優先)
  - 時計は加速して回す(営業5分を数秒で終える)
  - 開店準備では、雇用・解雇は**しない**(名簿は固定)。破産したら、そこで終了
- 日ごとに、次を記録して出力する(Console と CSV): 日数、お届け目安時間、売上、材料費、燃料費、日給、固定費、損益、所持金、評判、配達数、遅延数、キャンセル数、事故の回数
- **お届け目安時間を変えて比較**できる(例: 30秒・60秒・120秒の各設定で10日ずつ)。乱数のシードを指定でき、同じ条件で再現できる
- 既存のゲームの処理を使う(自動プレイ専用に、計算を別に書き直さない)

**完了条件**
- 10日分が自動で回り、日ごとの記録が出る
- 目安30秒・60秒・120秒で、売上・評判・破産するかが比較できる
- 同じシードで、同じ結果になる
- 自動プレイ中に、実行時エラーが出ない

**指示文**
> `Tools > Pizza Delivery > Simulate Days` というメニューを追加してください(Playモードで実行)。指定した日数(初期10日)を、自動で操作して回します。方針は、注文がある間、待機中で積載量の許す配達員に、`Dispatch with suggestion` と同じ推奨ルートで出発させることです(注文1件ずつ。同じ配達員の候補が複数あれば、期限が近い注文を優先)。時計は加速してください。開店準備では雇用・解雇をせず、名簿は固定、破産したらそこで終了します。
> 日ごとに、日数、お届け目安時間、売上、材料費、燃料費、日給、固定費、損益、所持金、評判、配達数、遅延数、キャンセル数、事故の回数を、Consoleと、CSVに出力してください。お届け目安時間(30秒・60秒・120秒など)と、乱数のシードを指定でき、同じシードで同じ結果になるようにしてください。既存のゲームの処理を使い、自動プレイ専用に計算を書き直さないでください。

**学べること**: ゲームを自動で回して、数値を測るやり方(バランス調整の道具)。

## リスク
| リスク | 対処 |
|---|---|
| コストが重すぎて、1日目で破産する | コストと開始資金をすべてInspectorにする。M5-6の自動プレイで当たりを付ける |
| 雇用・解雇で名簿が変わり、M4の画面が壊れる | M5-5の完了条件に「M4の画面がそのまま動く」を入れた。名簿は、すでにリストで何人でも扱える作り |

| 範囲が広がる | M5に入れるのは、この計画書の内容だけ。成長・訓練・素質はM6、広告・設備はM7 |
