# 配達操作の改善（2026-10-23）

ユーザーの追加依頼に基づき、従来の見た目限定の作業から、以下の操作・期限の変更へ範囲を拡張した。既存の調理・積載・経路・配達・減点処理を再利用し、作り直していない。

## 遊び方

1. 厨房で調理する。内勤は自動調理。手作りでは窯をクリックして取り出すと、自動梱包が始まる。
2. 下の「配達指示」（2 / Eでも可）を押す。専用の受け渡し画面へ移動する必要はない。
3. 左上の配達員の名前を選び、注文一覧の「積む」で持たせる。外したいときは「外す」。満杯・未調理・別の人に積載中の注文は積めない。
4. 持たせた注文の「届け先へ」、または地図のピンを行く順に押す。最後の届け先まで選ぶと帰路も付く。道路を直接クリックして組む方法も継続。「1本戻す」「店へ戻る」「やり直す」で修正できる。おすすめ経路も任意で使える。
5. 個別配達との時間比較と注文の残り時間を見て「出発」。配達中の注文も一覧に残り、到着までの秒数が出る。

厨房へ戻る操作は下の「厨房」、1 / Q。Escの遊び方も新しい操作へ更新した。

## 変更

- `BusinessView`の既存画面を使い、厨房・配達指示の2画面へ整理。旧Handoverの呼び出しは配達指示へ転送。非表示にはCanvasGroupを使う。
- 配達指示に、調理待ち・調理中・梱包済み・積載中・配達中の注文をスクロール表示。注文ごとに目安までの秒数、超過秒数、未出発の受付残り時間を表示する。
- 調理中の伝票にも残り秒数を追加。キャンセル時は通知し、一覧には理由を8秒間残す（UIThemeで調整可能）。
- 配達員を頭文字でなく名前で選べる。積み込みと届け先指定を注文ごとのボタンで実行できる。既存のバッグ・経路・出発の処理を呼ぶ。
- プレイヤーが窯から取り出した後は2秒で自動梱包（既存のpackSecondsを使用）。ラックの空きと梱包スロットを予約し、満杯なら保温棚で待ち、空くと再開する。内勤の作業時間・品質式は維持する。
- 注文の目安時刻を変更せず、未出発の受付期限だけ20秒延ばす。調理・選択・積載・出発・キャンセル・自動営業の判定をこの期限に合わせる。減点は元の目安時刻から始まる。
- 地図の道幅・縁・方向矢印に画面上の大きさを設定できるようにした。地図ピンのラベル背景も修正。MapManager、ManualDeliveryRoute、RoadPathfinder、MapDefinitionは変更していない。

## 判断した点

- 「若干」の初期値は20秒。`ScoreManager.lateAcceptanceSeconds`で調整可能。猶予の終了時刻ちょうどに未出発の注文はキャンセルする。閉店時の未出発分のキャンセルは従来どおり。
- 既に出発した注文は従来どおり、到着すると遅れでも配達成功。遅延減点は既存の毎秒5点・下限0を使用し、遅れた注文にはチップ・品質ボーナスを付けない。大幅な遅れを別の失敗へ変更する処理は足していない。
- 「自動梱包」は窯から取り出した後の箱詰めを自動化する意味で実装。手作りの焼き具合を見て取り出す操作・放置で焦げる仕組みは残した。内勤は取り出しも自動。
- 旧受け渡し部品とAPIは互換性のため保持するが、通常操作では表示・使用しない。既存セーブ形式は変更しない。
- これは追加依頼の範囲の変更。大規模地図・タイトル等、前の店内UI作業の未完了項目まで完了と扱わない。V-5・M4-9・C-5の調整は実施しない。

## 追加依頼(2) — 2026-10-23 Claude

| 依頼 | 実装 |
|---|---|
| 配達指示で現在の注文と進行状況が分かる | 注文一覧を短い行に変更。各注文に5段階の進行バー（調理→焼き→梱包→積載→配達）、状態バッジ、残り秒数を表示。梱包済み・積載中の注文だけに「積む/外す」「届け先へ」を出し、1画面で多く見えるようにした |
| 開始時に注文が入っている | `OrderSpawner.openingOrders`（初期2件）。開店の最初の時間進行で、目安時間付きの注文を2件発生させる |
| ボタンの中身が中央にない | `StickerButton`で文字を字形の中心で縦方向に揃え（日本語フォントの上下余白で下へずれていた）、アイコン・文字・▶をまとめて実測幅で中央に配置。バッジと頭文字も同様 |
| 梱包の時間を考慮しない | `CookingManager.packSeconds`=0（シーン保存）。窯から出た時点で箱詰め。内勤のピザも内勤の手が空くのを待たずに梱包。調理の標準時間`CookSeconds`は組み立て6+窯4=10秒に変わり、目安の下限が約37.81→35.81秒になった |
| 梱包済みを梱包待ちの場所にストック | 厨房右上の棚に梱包済みの箱（最大6）を並べる。番号・★・期限の帯付き。棚に空きがないときだけ焼き上がりのピザが「空き待ち」で並ぶ |
| 梱包済みを店にいる配達員へドラッグで積荷 | 厨房右下に「受け渡し」カウンターを追加。店にいる配達員の札へ箱をドロップするとバッグに入る（クリックで選択中/空いている配達員へ積む、配達員の札クリックで配達指示へ）。不在の配達員は受け付けない |
| お届け目安をスライダで変更 | 営業中の上の帯、開店準備の下の帯、経営タブをスライダに変更。範囲は物理下限〜上限。範囲の設定ではコールバックしない（初回に最小へ戻る不具合を防止） |

判断・注意
- 名簿を新しいゲームで作り直すと同じIDの別オブジェクトになるため、画面の再構築判定にIDだけを使うと古い配達員を参照し続けていた。店の画面と受け渡しの判定に参照の同一性を加えた（既存の潜在不具合の修正）。
- 自動営業（シミュレーション）にも開店時の2件と梱包0秒が効くため、経営の結果は変わる。数値は未調整。長時間シミュレーションは今回の方針により未実行。
- **事故報告**：確認用の撮影補助スクリプトで、営業開始時の保存を抑制していなかったため、通常セーブ`campaign.json`を新規ゲーム1日目の状態で上書きした（04:25）。復元用のバックアップはない。補助スクリプトは全体を保存抑制する形に修正済み。
